# Known Issues and Tech Debt

Each entry names the version that should clear it. See [roadmap.md](roadmap.md) for what each version delivers.

## Not yet play-tested

v0.5 and v0.6 pass the EditMode and PlayMode suites (including `LeakTests`), but nobody has played a full match with them yet. Check these in the first manual Linux match. **v0.6**

- **Fog overlay** (`Client/FogView.cs`): draw order over the instanced units and buildings, and that its colours look right.
- **Lobby team pills** (`LobbyController`): cycling a player's team as host (Teams mode), and seeing the change on other clients.
- **Allied play**: allies share vision and never fight; a team win shows the Win screen to every player on the team, including eliminated ones.
- **Building ghosts**: enemy buildings dim when out of sight and disappear only once their spot is seen again.
- **From the 2026-10-10 bug run:** clicking your own spawner selects it, right-clicking an enemy building attack-moves there, the settings panel stays put across tabs, and a refused join (match started, or 8 players) says so on the Play screen.
- **Editor crash after `SimData` gains fields.** The first EditMode run after `SimData`'s layout changes can segfault while scheduling a tick job (v0.5: `GatherJob`; v0.6 Task 4: `SimCombatSystem`, in `AtomicSafetyHandle` handle extraction). Restarting the editor fixes it every time, so it is stale Burst code compiled against the old struct layout. Restart the editor after changing `SimData`'s fields, before running the tests.

## Fixed in v0.6 (found by the first two-process run)

- `GameCore`'s `NetworkIdentity` in `Main_Menu` was **Server Only** (since the initial commit), so remote clients never received it: no game state, player list, HQ prompt or HQ placement, and every `GameCore` command was unusable from a joining client. The host worked because it is the server, which is why no hosted PlayMode test caught it. Fixed; `tools/qa-smoke.sh` now covers a real joining client. (Since the bug run, `GameCore` is a spawned prefab, see above.)
- `Run In Background` was off, so a player who alt-tabbed stopped updating (and a host froze the match). Now on.

## Fixed in the v0.6 bug run (2026-10-10)

Besides the owner's reports above:

- **Clicks on buildings never reached the world.** `GameInput.PointerOverUI` used `EventSystem.IsPointerOverGameObject()`, and `Map_2`'s camera has a `Physics2DRaycaster`, so the pointer counted as "over the UI" over every building collider and over the hidden hand-built `Walls` tilemap's collider (still active on generated maps, around tiles 29–91 × 45–96, a large part of a 256 map). Right-clicking an enemy building did nothing, and no box selection could start there. Physics raycaster hits no longer count as UI.
- **Clicking your own spawner raced box selection.** The spawner's `OnPointerClick` and `UnitCommander`'s box select both handled the same click, in no fixed order, and the box select cleared the building selection. `UnitCommander` now selects an own spawner on a click that hits none of your units.
- **The match-end wipe was silent.** `DeclareWinner` / `DeclareDraw` set _GameOver_, the tick stopped at the next boundary, and the wipe it then applied was never settled: no explosions, and no Leaves, so clients kept predicting the dead units behind the end screen. The tick now runs in _GameOver_ too (`SimBoundarySystem.RunsIn`), and explosions after _GameOver_ skip the fog test (`VisibilityRules.ShowsDeath`). At most 1,024 explosions go to one client per tick.
- **Players could join a running match, or a ninth player could join.** A late joiner had no team, colour slot, HQ or replication (and blocked the countdown in _PlacingHQ_); a ninth got a duplicate colour. The server now closes connections outside the lobby or beyond 8 players (`LobbyRules.MayJoin`), and the joining client says why.
- **Ctrl+number with nothing selected didn't empty the squad on the server.** The client cleared its copy and sent an empty chunk, which the server rejected as malformed; the squad bar then showed the old count. An empty chunk now means an empty squad.
- **Footprint writes raced the tick.** `MapStore.SetUsed` wrote the map's `Used` array (which the movement job reads) from the main thread whenever a building was placed or destroyed between ticks. Footprint changes are now queued (`MapStore.QueueUsed`) and applied at the next boundary; placement and spawn checks see queued changes at once.
- **`Cmd_SetTeam` ignored the lobby's rules.** The host could put players on teams 0–15 even in Free-for-all; it now takes only the choices a player could make (`LobbyRules.IsTeamChoiceValid`).
- **The player order didn't match the lobby.** `PlayerOrder` followed the server's dictionary order, which differs from join order after someone leaves, so the camera could start on another player's clearing. It is now sorted by net id, as the lobby is.
- **The selection box stopped growing** past about 31 tiles from where the drag began (the selection itself was right).
- Developer console commands threw when no match was running.

## Developer tools

- **The editor froze once during a PlayMode run** (2026-10-10, KDE Wayland, Vulkan): after `HudTests`' eighth match the main and render threads sat in futex waits with no CPU use for over 40 minutes, so the pipeline's requests timed out. Killing and reopening the editor fixed it, and the same suite then passed in full. If `tools/unity-test.sh PlayMode` stops reporting progress, check the editor window is visible before suspecting the tests. (no target)
- **Bots look eliminated in the HUD.** Dev bots (`GameCore.AddBot`, perf harness and tests) have no player object, so the top bar and diplomacy panel list them as "Player (eliminated)" with disabled switches, and their diplomacy bit reaches clients only after `SendAllDiplomacy` is called again (bots join after match start). Dev only; real players are unaffected. (no target)

## Project and config hygiene

Inert leftovers disclosed in v0.2 and scheduled to be cleaned up together.

- **No Windows build profile.** Only `Assets/Settings/Build Profiles/Linux.asset` is checked in — the owner deferred Windows to a later release. **v0.9**
- **Vendored Mirror components still call the legacy `Input` API** — `Components/GUIConsole.cs`, `Components/RemoteStatistics.cs` and `Components/Profiling/ToggleHotkey.cs` (the last via its own `GraphCanvas.prefab`). None are used in the shipped scenes, and the project is Input System only (`activeInputHandler: 1`), so they would throw if ever attached. Not shipped; leave vendored code alone (no target).
- **Vendored Console `Demo/Scripts/DemoPlayer.cs` uses the legacy `Input.GetAxis`.** Demo only; not used by any shipped scene. Not shipped; leave vendored code alone (no target).
- **Every unit type draws with the Tank texture.** `InstancedUnitRenderer` binds one texture; per-type frames come with the sprite atlas in the art pass. **v0.8**
- **Rebinding checks conflicts against hidden actions too.** `Rebinding.ConflictWith` looks at every action in `GameInput.Map`, including ones the Controls page doesn't list (the squad keys, `FastPan` and `AppendModifier`, which share Shift with Queue order). Binding Stop to `1` reports a conflict with "Squad1", and Swap gives that hidden action the old key. Show those actions or skip them in the check. **v0.7**
- **`Acceleration` is parsed but unused.** `GameConfig.xml` and `gameplay.md` list it, but units reach full speed at once. Use it or drop it with the v0.7 units. **v0.7**
- **Footprints ignore rotation.** `Footprint.Tiles` and the building sprite's placement assume a square footprint, so a rotated non-square building (Width ≠ Height) would cover the wrong tiles. Every building is square today. **v0.7** (walls and new buildings)
- **`UnitCommander` keeps SyncList-era handlers** (`BuildingListSet`, `BuildingListClear`, `HealthList*`) that nothing calls since v0.5's building records. Remove them with instanced buildings. **v0.7**
