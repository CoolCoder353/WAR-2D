# v0.18 Briefing Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Show players what they need to know (Field manual, rings, end-screen graphs and timeline, replay graphs, markers and a per-player view), take friction out of everyday actions (Attack order, a drag box that prefers the army, Rematch, remembered lobby settings), and make Suicide bombers explode at 10 % health and aim for the middle.

**Architecture:** Pure rule classes first (`RangeRings`, `SelectionRules`, `SummaryRules`, `ManualRules`, `RematchRules`, `LobbyMemory`), each with EditMode tests, then the sim stages, wire and UI on top. Everything sim-side stays in the tick's rules: main-thread code queues `SimCommand`s; new per-unit arrays are written only at the boundary or by a declared stage. New client data follows the leak rule (spec, opening of section 1).

**Tech Stack:** Unity 6000.4.1f1, Unity Entities (DOTS) sim, Mirror, UI Toolkit (`Painter2D` for charts), NUnit through `tools/unity-test.sh`, the control API (`tools/war2d`), Node for `tools/manual-mock.js`.

**Spec:** [docs/superpowers/specs/2026-11-03-v0.18-briefing-design.md](../specs/2026-11-03-v0.18-briefing-design.md). **Figma:** [brief](../../ux/v0.18-figma.md), page `v0.18 Briefing` (node 188:2).

**Progress (2026-11-03):** Tasks 1 to 14 are committed, with a hosted Rematch PlayMode test. `CursorAttack` needed no change for D16: `PixelIcons` already outlines cursors.

- Approved frames (G1, E1, E2, R1, O1, L1) are built as drawn. **The manual (Tasks 13, 14) isn't built until the owner approves F1–F3.**
- `WarLog`, never `Debug.Log`. XML summaries on public members. Docs updated in the same task where behaviour changes; `gameplay.md`'s tables when numbers change.

### Task 3: Bombers: last gasp

**Files:** `Sim/SimCombatSystem.cs`, `SimData.cs`, `known-issues.md`, `gameplay.md`; test `SimBomberTests`.

**Produces:** `LastGaspJob` after `ApplyDamageJob`, running `Bomber/ChainPasses` passes.

- [ ] Tests: shot to 0 explodes where it fell and hurts both sides; a Digger's hit leaving it at 2 sets it off; decay sets it off; three chained go off in one tick; a chain past the fourth pass waits for the next tick; a bomber already detonated doesn't go twice; kill credit goes to the bomber's owner.
- [ ] Extract `Detonate` into a shared static `BomberBlast.Enqueue(...)` used by both jobs. `LastGaspJob` compares start-of-tick health (a snapshot array `BomberHealthAtStart`, or the hits' effect) with health now: crossing `LastGaspHealth × max` detonates.
