# v0.21 Warpath Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An AI that reaches or breaches what it attacks, never sits on an idle army, defends the lanes it is attacked
through, and spends what it earns (expansions, forward bases, fortifications).

**Architecture:** Every change is inside the AI (`Assets/Scripts/Ai/`), which reads only its `TeamView` and acts only
through `AiAction` / `PlayerActions`. A new per-brain `ReachMap` answers "can my units get from A to B over the ground
I know, and which walls are in the way?"; the managers build on it phase by phase. New numbers go in `GameConfig.xml`
`<Ai>`, parsed strictly by `ConfigParser`.

**Tech Stack:** Unity 6000.4.1f1, C#, NUnit (EditMode with `AiSandbox`, PlayMode with `PlayModeMatch`), node tools
for the bench brief.

**Spec:** [docs/superpowers/specs/2026-11-22-v0.21-warpath-design.md](../specs/2026-11-22-v0.21-warpath-design.md)

## Global Constraints

- The AI knows only its `TeamView` and acts only through `AiAction` within its action budget; `AiLeakTests` keep passing.
- Every difficulty plays the same policy through handicaps; Hard plays it as is.
- No balance changes: no unit, building, cost or income numbers move. The rich-gem economy is out of scope.
- Every new number lives in `GameConfig.xml` `<Ai>` and is parsed with a range by `ConfigParser`; no hard-coded tuning.
- Logging through `WarLog` with a category; `/// <summary>` on public members.
- Compile with `tools/unity-compile.sh` while working; `tools/check.sh` (editor closed, the Steam copy of WAR closed:
  PlayMode hosts on port 7778) passes before each phase lands.
- Each phase ends with `tools/ai-bench.sh --brief` against a fresh `Builds/Linux` build
  (`-executeMethod WAR2D.EditorTools.BuildCommands.LinuxBench`), compared with the previous phase's.
- Commits: no co-author or AI attribution lines (CLAUDE.md).

## Phase 1: reach map and breaches

**Design change from the spec (§3):** the reach map works on tiles, not 4-tile cells. A one-tile wall inside a 4-tile
cell would leave the cell "open". Units can't cut corners diagonally (`FlowField`), so 4-connected floor components
match where units can walk. Walls join components through a small graph of wall tiles, so a breach query only searches
the walls, not the map.

### Task 1.1: `ReachMap`

**Files:**
- Create: `Assets/Scripts/Ai/ReachMap.cs`
- Test: `Assets/Tests/EditMode/ReachMapTests.cs`

**Interfaces:**
- Produces:

```csharp
public enum Reach : byte { Open, Walled, Cut }
public sealed class ReachMap
{
    public ReachMap(int width, int height, int tilesPerStep = 1 << 20);
    /// Full relabel from the known tiles at once (tests; first use).
    public void Rebuild(byte[] tiles);
    /// Marks a relabel due; Step does it over several calls, tilesPerStep tiles at a time; queries use the last finished labels.
    public void MarkDirty();
    public bool Step(byte[] tiles);           // true when a relabel finished on this call
    public int Version { get; }               // bumps on each finished relabel
    public int ComponentAt(int2 tile);        // -1 on a non-floor tile
    public int2 NearestFloor(int2 tile, int radius);
    /// wallCost(tileIndex) > 0: the cost of breaking that wall tile. breach gets the wall tiles to break, from the 'from' side.
    public Reach Query(int2 from, int2 to, byte[] tiles, System.Func<int, float> wallCost, List<int2> breach, out float cost);
}
```

- [ ] **Step 1:** Write the failing tests (a 16×16 grid built in the test):
  `OpenFloorIsOpen`, `RockSplitIsCut`, `OneWallTileIsAOneTileBreach` (a vertical `PlayerWall` line splits the map: breach
  of one tile, on the line, cost = its wall cost), `ThickerWallCostsMore` (two layers: two tiles, cost doubled),
  `TheCheapestBreachWins` (a weak tile in a strong line: that tile), `AWallBlueprintIsFloor`,
  `SlicedRelabelMatchesAFullOne` (Step with 37 tiles per step gives the same components as Rebuild),
  `QueriesUseTheLastFinishedLabels` (dirty and mid-relabel: the old answer).
- [ ] **Step 2:** `tools/unity-test.sh EditMode` filtered to `ReachMapTests` → fail (no type).
- [ ] **Step 3:** Implement (labels by iterative 4-connected flood fill over `TileRules.IsFloor`, double-buffered int
  arrays; a breach is Dijkstra over nodes = components ∪ wall tiles, entering a wall tile costs `wallCost`, entering a
  component costs 0, a component's wall neighbours found by scanning the wall tiles once per query; results cached by
  (from component, to component, `Version`) until `MarkDirty`).
- [ ] **Step 4:** Tests pass.
- [ ] **Step 5:** Commit `AI: the reach map (v0.21 §3)`.
