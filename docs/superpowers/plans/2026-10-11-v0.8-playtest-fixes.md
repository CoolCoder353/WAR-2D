### P1: Units shoot through walls (HQ attacked through rock)

`SimCombatSystem`/`TargetSearch` pick targets by range only; only `SimVisionSystem` traces lines of sight.
- [x] Failing EditMode test: an enemy in range behind a wall row is not targeted; the same enemy with a gap is.
- [x] Add a Burst tile ray (the vision system's trace, shared as a static helper) to target acquisition and to each shot's validity check.
- [ ] Perf gate (ray cost × attackers per tick).

**As built (84dc6b0):** `Sim/LineOfSight` (Bresenham over `SimData.Opaque`, end cells skipped) is used by `StampVisionJob`, `NearestEnemyJob` (only for a candidate nearer than the best so far) and `ResolveTargetsJob`. Buildings are traced to their position, not any footprint tile.

### P2: Units stuck on walls

Hypothesis: units steered by the 2×2-tile flow field into a wall-holding cell pin against corners (see the comment at `SimMovementSystem.cs:180`), or the separation push shoves them into walls.
- [x] Reproduce: EditMode tests `CrowdCrossesAStaircaseWallThroughAOneTileGap` (12 units, odd-aligned diagonal wall, 1-tile gap) and `CrowdCrossesAGeneratedCaveMap` (40 units across 128² generated maps, 3 seeds). **Both pass without changes**: the sim routes crowds around walls.
- [ ] Owner re-test after P3. Most likely cause: orders whose goal was rock or a building footprint (a minimap click on unknown rock, or a right-click on the enemy HQ) had no reachable goal cell, so units piled against the nearest wall. P3 fixes that. If units still stick, note the spot (screenshot with the minimap) so it can be reproduced.

### P3: Minimap order onto an unknown wall makes units wander

- [x] Failing test: a move goal on a wall/gem tile is snapped server-side to the nearest reachable floor tile (BFS from the goal, capped radius) before the order is issued; with none in range the order is dropped.
- [x] Applies to all move/attack-move goals, not only the minimap. The client never learns the hidden tile type (`LeakTests`).

**As built (84dc6b0):** `OrderBook.SnapGoal` in `OrderBook.Issue`: nearest walkable tile within `GoalSnapRadius` = 12, ties to the side of the first unit; none → `Issue` returns -1 and the order is dropped.

- [ ] Fix and add a test on the blend (correction error decays, never jumps more than X per frame).
