> **For agentic workers:** work task by task on `release/v0.8`. Both suites pass per task (`tools/unity-test.sh EditMode|PlayMode`); re-run `tools/perf-run.sh` after any change to the tick, pathing or replication. Check boxes and add "As built" notes. Gameplay numbers go in `GameConfig.xml`; HUD changes go through Figma first.

**Goal:** fix the owner's 2026-10-11 playtest bugs (`docs/known-issues.md` → *Owner playtest bugs*) before the v0.8 close-out (New Paint Task 16).

**Order:** bugs that break matches first (P1–P4), then a control-discoverability fix (P5), then features the owner asked for (P6–P9, one Figma pass for all their HUD changes), then the networking items (P10–P11) which get their own spec.

## Review of the earlier fixes (97c0be1)

- **Placement feedback:** sound. The preview stays neutral until the server answers for the exact spot, type and rotation, and stale answers are ignored. It tints pure green/red (off-palette) plus a 1.1× outline sprite; acceptable for readability, but P6's Figma pass should pick palette colours and add a non-colour cue (icon or hatch) for colour-blind players.
- **Building rotation:** works, but rotation is cosmetic only (no system reads `BuildingData.rotation`), and spinning a 3/4-view sprite turns its baked shadow and light the wrong way. P9 replaces it with rendered facings.

### P1: Units shoot through walls (HQ attacked through rock)

`SimCombatSystem`/`TargetSearch` pick targets by range only; only `SimVisionSystem` traces lines of sight.
- [ ] Failing EditMode test: an enemy in range behind a wall row is not targeted; the same enemy with a gap is.
- [ ] Add a Burst tile ray (the vision system's trace, shared as a static helper) to target acquisition and to each shot's validity check; buildings count as hit if the ray reaches any footprint tile.
- [ ] Perf gate (ray cost × attackers per tick).

### P2: Units stuck on walls

Hypothesis: units steered by the 2×2-tile flow field into a wall-holding cell pin against corners (see the comment at `SimMovementSystem.cs:180`), or the separation push shoves them into walls.
- [ ] Reproduce in a PlayMode test: 50 units ordered through a 1-tile gap and around an L corner all arrive within N ticks.
- [ ] Fix the cause found (likely: steer along the tile-level direction near walls, and clamp separation against solid tiles). Perf gate.

### P3: Minimap order onto an unknown wall makes units wander

- [ ] Failing test: a move goal on a wall/gem tile is snapped server-side to the nearest reachable floor tile (BFS from the goal, capped radius) before the order is issued; with none in range the order is dropped.
- [ ] Applies to all move/attack-move goals, not only the minimap. The client never learns the hidden tile type (`LeakTests`).

### P4: Unit movement not smooth

Client-side: `ClientWorld` prediction vs `ReplicationService` corrections.
- [ ] Measure first: log per-unit correction size and frequency in a QA smoke match; check interpolation runs per frame, not per tick, and that corrections blend over several frames instead of snapping.
- [ ] Fix and add a test on the blend (correction error decays, never jumps more than X per frame).

### P5: Squads are hard to discover

Squads exist (`Ctrl`+`1`–`0`, squad bar), but the owner couldn't find them.
- [ ] Figma (with P6): empty squad slots show `Ctrl+1` hints; a first-match tip line. Then implement.

### P6: Spawner rally points

- [ ] A spawner keeps a rally tile (server-side, validated like a move goal, P3 snapping); right-click with only spawners selected sets it; new units get a move order there. Draw the rally flag (already in the Effects atlas) for own spawners only.

### P7: Multi-spawner production and +10/+50

- [ ] Selecting several spawners lets the production queue's buttons queue on each. Add +10 and +50 buttons (Figma first), capped by `GameConfig.xml` queue limits; the server validates every spawner's ownership.

### P8: Place several buildings in a row

- [ ] Holding `Shift` while placing keeps the preview active after each placement (as `Shift` queues orders). Document in `gameplay.md`.

### P9: Building facings instead of sprite rotation

- [ ] Owner decision first: (a) render 4 facings per rotatable building in `RenderGen` (atlas ×4 for those buildings) and pick the frame by rotation, keeping the sprite upright; or (b) drop the Rotate key, since rotation has no gameplay effect. Recommended: (a) for the miner only, (b) for the rest.

### P10: Spectate for defeated players

- [ ] A defeated player can stay and watch: vision of all teams (server sends all fog and units to that connection only after defeat; `LeakTests` gain a case that it never happens before). Needs Figma for the spectate bar.

### P11: Host leaving ends the match for everyone

Mirror's host-client model: the server dies with the host. Host migration is out of scope for v0.8.
- [ ] Short term: clients get a clear "the host left the match" screen instead of a dead game.
- [ ] Longer term (roadmap v0.9 decision): a dedicated-server option.
