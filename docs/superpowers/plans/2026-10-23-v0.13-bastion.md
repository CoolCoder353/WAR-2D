# v0.13 Bastion Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. This plan lists each task's files, steps and tests; write the code against the files as they are when you start (read them first).
> Project rules that apply to every task: compile with `tools/unity-compile.sh` while working; run **both** suites (`tools/unity-test.sh EditMode`, `tools/unity-test.sh PlayMode`) **once at the end of the whole plan** (the owner's preference, 2026-10-16), not after every edit. Commit only when the owner has asked for it, on `release/v0.13`, never from `main`, and **never add a co-author or AI attribution line** (`CLAUDE.md`). Don't hand-edit `.csproj`/`.slnx`, scene, prefab or `.asset` files. Don't edit vendored code. Restart the editor after changing `SimData`'s fields, before running tests (`known-issues.md`, Developer tools).

**Goal:** Two static defences built by Builders from blueprints: the **Gun turret** (the first building that attacks: units, then buildings, then walls, like a unit that can't move) and the **Jammer** (inside its radius, enemies see only within `JamSight` and enemy Radars see nothing).

**Spec:** [2026-10-16-v0.13-bastion-design.md](../specs/2026-10-16-v0.13-bastion-design.md) (every number and rule; approved 2026-10-16). Parent: [roadmap](../../roadmap.md) §2 v0.13. HUD: `docs/ux/v0.13-figma.md` (written in Task 0).

**Starting point (owner, 2026-10-23):** v0.12 is finished: its security review, code review and full Linux match are done and found nothing. v0.13 builds on `main` as merged from `release/v0.12`.

## Global constraints

- Server-authoritative as always: buildings are created only by `SimCommandSystem.CreateBuilding`; main-thread code never touches `Unit` entities or `SimData` arrays between ticks; new tick work declares write access to `Unit` and schedules Burst jobs on `state.Dependency`. `ApplyDamageJob` stays the **single writer** of unit, building and wall health: the turret only queues `DamageHit`s.
- The turret's targeting is the unit rules, not a copy of them: one shared search (Task 4). "Enemy" means an owner on the turret owner's attack mask (`SimData.AttackMask`), never just a different owner.
- Fog is the only gate on what clients learn. The jam works by changing what a grid sees, so fog interest, building interest, terrain deltas, explosions and alerts all follow it with no per-message special case. Anything new sent to clients (building attacks) follows `BuildingInterest`'s may-know rule. `LeakTests` must keep passing.
- Every balance number in `GameConfig.xml`, parsed strictly. No new hard-coded numbers.
- No new `[Command]`s are needed (both defences are placed through the existing build path). If one becomes necessary: `requiresAuthority = false`, `NetworkConnectionToClient sender = null`, `CommandGate.Allow` first with a budget entry, ownership and value checks, fuzz tests.
- Any HUD change beyond the approved frames goes back through Figma first.
- Perf budget: ≤ 25 ms main-thread tick p95 at 80,000 units with defences in the siege load (`tools/perf-run.sh`); results in `docs/perf/v0.13/`.

### Task 1: Config schema

**Files:** `Config/GameConfig.cs`, `Config/ConfigParser.cs`, `Rules/DamageTable.cs`, `Resources/GameConfig.xml`, `Tests/EditMode/ConfigParserTests.cs`.

- [ ] `<Building>` gains optional `<Damage>`, `<Range>`, `<AttackInterval>` (all three or none; `Damage > 0` makes it an attacker; a `Range` or `AttackInterval` ≤ 0 on an attacker is an error).
- [ ] `<Siege>` gains `<JamRadius>` and `<JamSight>` (both > 0; `JamSight < JamRadius`).
- [ ] The damage table accepts attacker **building** types: `<Entry attacker="GunTurret" target="LightUnit">`. `DamageTable` attacker index = `UnitType` value, or `UnitTypeCount + (int)BuildingType` for buildings; `DamageTable.Get(attacker, targetClass)` callers pass the index through a helper (`DamageTable.UnitAttacker(type)`, `DamageTable.BuildingAttacker(type)`) so nothing hand-computes offsets. A building attacker with no row is an error at load.
- [ ] Add the spec §5 `GunTurret` and `Jammer` entries and the damage row (LightUnit 1.5, HeavyUnit 0.4, Building 0.5, Wall 0.5), marked as starting values in a comment.
- [ ] Tests: the new fields parse; a partial weapon block is an error; a building attacker without a table row is an error; `target="Unit"` shorthand works for building rows; `ConfigLoader.IsValid` on the shipped file.

### Task 4: Turret targeting and firing

**Files:** `Sim/TargetSearch.cs`, `Sim/SimCombatSystem.cs`, `Sim/SimData.cs` (attack events), `Tests/EditMode/CombatTests.cs` (or the existing combat test file).

- [ ] **Share the search.** Pull the body of `NearestEnemyJob.Execute` (unit scan, then building scan, then `FindWall`) into a static Burst-compatible `TargetSearch.Nearest(in SearchInput, float2 p, int slot, float rangeSq, float minSq, bool walls, out int target, out byte kind)` that both jobs call. The unit job passes `walls = Stance == AttackMove` (today's behaviour); the turret always passes `walls = true` (spec §2.1: units, else buildings, else walls). Unit behaviour must not change: the existing combat tests are the guard.
- [ ] `ResolveBuildingTargetsJob` (over `AttackerBuildings`): drops a stored target that died, left range, lost line of fire, went into the fog of the turret owner's grid, changed hands, or is no longer attacked (diplomacy), exactly as `ResolveTargetsJob` does for units (share its checks the same way).
- [ ] `BuildingTargetJob`: sliced over ticks like units (`(i + Tick) % Slice`), skips non-complete or `Unpaid` buildings, calls `TargetSearch.Nearest`.
- [ ] `BuildingAttackJob`: cooldown from `BuildingIntervalByType`; on fire, a `DamageHit` (unit or building) or a wall hit into the existing queues, with damage `BuildingDamageByType × DamageTable[BuildingAttacker(type), class]`. Schedule it before `ApplyDamageJob` so the single writer applies it.
- [ ] **Attack events gain an attacker kind.** `SimData.AttackEvents` (`NativeList<int2>`) becomes a list of a small struct `{ int Attacker; int Target; byte AttackerKind; byte TargetKind }` (or keep `int2` and add a parallel `BuildingAttackEvents` list: pick the one that changes fewer readers; `AlertService`, `ReplicationService` and the recorder read it). `AlertService`'s Under-attack alert fires for a turret's victims like any other attack, and a turret being hit raises the owner's existing Under-attack alert.
- [ ] Tests (EditMode, world-level like the v0.12 combat tests): a turret fires at an enemy unit in range, line and sight; prefers a unit over a building over a wall in range; doesn't fire as a blueprint, while unpaid, at allies or their walls, at owners not on its attack mask, into the fog, through rock, or beyond range; damage-table multipliers (Scout vs Heavy targets); cooldown is `AttackInterval`; a unit's targeting is unchanged (the existing tests).

### Task 5: Turret on clients (after the owner's Task 0 approval)

**Files:** `Net/Replication/Messages.cs` (`AttackEvent` encode/decode), `Net/Replication/ReplicationEncoder.cs`, `Net/Replication/ReplicationService.cs`, `Net/Replication/BuildingReplication.cs` (`BuildingInterest`), `Client/ClientWorld.cs` / `ClientBuildings`, `Client/Render/InstancedBuildingRenderer`, `Client/Effects.cs`, `Audio/AudioService`, `Net/Replay/` (recorder and player), `Tests/EditMode/LeakTests.cs`.

- [ ] Wire: `AttackEvent` gains the attacker kind (one bit folded into the existing varint, or a byte). For a building attacker the event names the **building id**, not a unit index.
- [ ] Encoder: a building's attack goes to a client only when that client may know the building (owns it, or its grid sees the building now; the rule `BuildingInterest` applies), and the target is named by the existing `MayKnowTarget` / `AttackTarget` rule, else sent as 0.
- [ ] `ClientBuildings`: per turret, the head's facing (one of 8) turns toward the last target the client was told about; the renderer draws the head over the base. Tracer from the turret's centre, `TurretMuzzle` flash, `shot_turret` through `AudioService` (it only follows events the client already draws).
- [ ] Replays: the recorder writes the new event kind; bump the recording format version and have the player refuse older or newer files with the existing message.
- [ ] LeakTests: a turret's attack never reaches a client that may not know the turret (a turret in the fog shooting a unit the client can see sends the client the damage via health, never the attack event or the turret's id).
- [ ] PlayMode: a client sees a turret's tracer and the head turn when it shoots that client's unit.

### Task 6: The jam mask

**Files:** `Sim/SimData.cs`, `Sim/SimVisionSystem.cs`, `Sim/SimContext.cs` (dirty flag hooks), `Sim/Diplomacy.cs`, `Net/RadarService.cs`, tests.

- [ ] `SimData.JamMask`: one byte per fog cell **per owner slot** (`slots × FogCells`, same layout as `Visible`); `JamDirty` flag. A cell of grid *g* is jammed when it lies within `JamRadius` of any complete, paid Jammer whose owner is not *g*'s owner and doesn't share vision with *g*'s owner (spec §3.1).
- [ ] `RebuildJamJob` runs in the vision stage only when `JamDirty`: set when a Jammer completes, dies, becomes unpaid or paid again, and when share-vision changes (`SetShareVision` at the boundary). Not every vision pass.
- [ ] `StampVisionJob`: a source stamping grid *g* marks a jammed cell visible only if the source is within `JamSight` of it (line of sight still required). Shared sources stamp other grids with **those** grids' jam masks.
- [ ] `StampRadarJob`: skips jammed cells of the grid it stamps. `RadarService.Update`: no contact and no ping for a unit on a jammed cell of the Radar owner's grid.
- [ ] Spectators: an eliminated player already gets the whole map; check the jam doesn't reach that path.
- [ ] Tests (EditMode): the mask is built when a Jammer completes, cleared when it dies or goes unpaid, never set for its owner or anyone it shares vision with, rebuilt on a share-vision change; a unit sees a jammed cell within `JamSight` and not beyond; a Radar is blind in jammed cells and never pings for a jammed contact; the Jammer itself is seen by enemies only up close (a ghost stays a ghost).

Run it with a third player's unit in the area too (area-wide jam).
