# v0.3 "Scale Spike" Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Measure, on the reference machine, whether the techniques chosen for 80,000 units actually fit the performance budget, and record a go/no-go decision for each one. v0.4 doesn't start until every row of the results table has a measurement and a decision.

**Architecture:** A throwaway prototype in its own assembly (`WAR2D.Spike`, `Assets/Spike/`) and its own ECS `World`, driven by a code-built scene. It doesn't touch game code. Each technique is a Burst job (or a set of them) with an EditMode correctness test, plus a benchmark mode in a Linux **player build** that writes its timings to CSV. The spike code lives on `spike/v0.3` and is **never merged**. It's tagged so v0.4 can read it back. Only the results, the docs and the housekeeping go to `main`, through `release/v0.3`.

**Tech Stack:** Unity 6000.4.1f1, Entities 6.4.0, Burst 1.8.28, Collections 2.x, Mathematics, Mirror 96.0.1 with kcp2k (MTU 1200, reliable max message 297,433 B, unreliable max 1,194 B), URP 17.4 (2D Renderer), Unity Test Framework 1.6.

**Spec:** [roadmap design spec](../specs/2026-10-05-war2d-roadmap-design.md): the §3 v0.3 row, §4.1 budgets, §4.2–4.5 target architecture, and §4.6, the results table this plan fills in. Also read [roadmap.md](../../roadmap.md) §3 (v0.3) and §6 (risks).

- **Don't edit vendored code** (`Assets/Mirror/`, `Assets/Plugins/Demigiant/`, `Assets/3rd Party/`). The spike references `kcp2k` and `Mirror` as they are.
- **Branches:**
  - `release/v0.3` holds the housekeeping (Task 1) and the results docs (Task 11). Its PR into `main` contains **no spike code**.
  - `spike/v0.3` branches from `release/v0.3` and holds all spike code. It's pushed and tagged `v0.3-spike` at the end, and **never merged**.
- After every code change on `spike/v0.3`: `tools/unity-compile.sh` must print `Compile OK`, and `tools/unity-test.sh EditMode` must pass, including the `WAR2D.Spike.Tests` tests.

## Measurement protocol

Every number in the results table is produced this way. Record the machine details once at the top of `docs/spike/v0.3-results.md`.

1. **Machine:** the reference machine (Ryzen 5 5600GT, 32 GB, RX 6600, Linux). Record `uname -r`, `lscpu | head -20`, the Mesa/AMDGPU driver version (`glxinfo -B`) and the Unity version.
2. **Build:** `Spike ▸ Build Linux Player` (Task 2). It's a non-development player (`BuildOptions.None`) with Burst AOT, so there are no safety checks and no job debugger.
3. **Quiet machine:** close the editor and browsers before running. Set the CPU governor to performance (`sudo cpupower frequency-set -g performance`) and restore it afterwards.
4. **Runs:** each configuration runs **3 times**. A run discards its first **100 ticks** (or 300 frames) as warm-up, then samples **600 ticks** (or 1,800 frames). Report the run whose p95 is the median of the three.
5. **Statistics:** mean, p50, p95, p99 and max (`SpikeStats`). **Decisions use p95**, except bandwidth, which uses the average plus the worst 1-second window.
6. **Server benchmarks** run headless (`-batchmode -nographics`). **Rendering and combined runs** run windowed at 1920×1080 with vsync off (`QualitySettings.vSyncCount = 0`, `Application.targetFrameRate = -1`).
7. **Wall time vs worker time:** for every tick-based benchmark, record **tick wall time** (schedule → `Complete()`, measured synchronously) and **main-thread time** (measured in async mode, where the tick's jobs complete at the next tick boundary). The host renders at 60 fps, so a tick that blocks the main thread for 25 ms drops frames even if it's "in budget". Task 10 decides which mode v0.4 uses.

## Go/no-go rules and fallback ladders

A row is **go** if its budget is met in the default configuration. Otherwise, try its fallbacks **in order** and record the first one that passes. A row is **no-go** only when every fallback fails. Then the owner decides between scaling the target down and changing the architecture before v0.4 starts.

| Row | Fallback ladder (in order) |
|---|---|
| Simulation | 1. Target search every 8 ticks instead of 4. 2. Separation every 2 ticks. 3. Movement integration in 2 halves on alternate ticks. 4. Owner decision: lower the unit cap (for example 5,000 per player). |
| Flow fields | 1. Lazy rebuild: only fields that have units still following them are rebuilt, at most 2 per tick. 2. Hierarchical 32×32 sectors (Task 4 Step 6). 3. Half-resolution fields (2×2 tiles per cell). 4. Cap live fields with LRU eviction. |
| Spatial hash | 1. Cell size sweep (4, 5, 8). 2. Slice interval 8. 3. `NativeParallelMultiHashMap` variant instead of the counting sort. |
| Fog | 1. 3 Hz instead of 5 Hz. 2. Vision grid at 2×2 tiles. 3. Radius-only vision for units, line of sight kept for structures. |
| Rendering | 1. Upload only changed instances. 2. `BatchRendererGroup`. 3. Aggregate distant units into blobs when zoomed out. |
| Bandwidth | 1. Corrections capped at 5 Hz per unit. 2. Coarser quantisation (1/8 tile). 3. Group orders sent once, with one shared route instead of per-unit waypoints. 4. Recommend dedicated servers for 8-player matches. |
| Combined host | 1. Async tick (jobs complete at the next tick boundary). 2. Lower the host's own render cost (fallbacks in the rendering row). 3. Recommend a dedicated server for 8 × 10k. |

### Task 0: Preconditions and owner decisions

Nothing is built until these are settled. They're the owner's calls, and changing them later invalidates measurements.

- [x] **Step 1: Confirm v0.2 is done.** The owner confirmed the manual 2-player Linux match (v0.2 plan, Task 17 Step 4) passed. It's recorded in the v0.2 row of `docs/roadmap.md`.

- [x] **Step 2: Owner decisions** (agreed 2026-10-05; copy them into `docs/spike/v0.3-results.md` under "Decisions taken before measuring"):
  - **D1. Map size: 512 × 512 and 1024 × 1024, both measured.** The owner accepted 512² on condition that it suits this many units. It's tight, not comfortable:
    - At 30 % rock, 512² has about 183,000 walkable tiles, so roughly 23,000 per player.
    - With the size mix in D2 (an average body of about 0.5 tiles²), 80,000 units cover about **22 %** of the walkable ground at 512², but only about **5 %** at 1024².
    - So 512² is the right **stress** size (the most crowded case for combat, the spatial hash and separation) but probably too cramped to play on. 1024² is the realistic candidate, and it's the worst case for flow fields, fog grids and memory.
    - Every row is measured at both sizes. v0.4 picks the shipped map size from the results.
  - **D2. Unit density model: continuous positions, shared tiles, separation steering, with mixed unit sizes.** The owner accepted this on condition that separation works for differently sized units. On its own, separation handles sizes well, but it has two limits, and the spike tests both:
    - **It's a soft constraint.** Units push apart when `distance < rᵢ + rⱼ`, and the smaller unit takes more of the push (weighted by the other's radius²), so small units make way for big ones. Under heavy crowd pressure, bodies can still overlap. Task 6 measures how much (`sim.overlap`) and how stuck large units get.
    - **It doesn't stop a big unit from trying a gap it can't fit through.** That's a pathfinding job: each size class follows a flow field built only over tiles with enough **clearance** (Task 4). The cost is a second field for every order that includes large units, and Task 4 measures it.
    - Today's one-unit-per-tile `TileOccupancy` can't hold 10k units per player and is retired in v0.4.
  - **D3. Budget split: 14 / 5 / 2 / 4 ms.** Accepted as proposed.
  - **D4. Defaults, with extreme vision ranges.** The reference load and battle layout are accepted. Vision is swept to extremes (units 6–32, buildings 10–20). The default of 8 is what the go/no-go uses, and each row also reports **the largest radius that still fits its budget**.
  - **D5. Wire-byte capture with `sudo tcpdump`:** allowed on the reference machine (Task 9 Stage B).

```csharp
using System;
using System.Collections.Generic;

namespace WAR2D.Spike
{
    /// <summary>Collects samples (ms, KB/s, fps...) and reports mean, percentiles and max.</summary>
    public sealed class SpikeStats
    {
        private readonly List<double> samples = new List<double>();

        public int Count => samples.Count;

        public void Add(double value) => samples.Add(value);

        public double Mean
        {
            get
            {
                if (samples.Count == 0) return double.NaN;
                double sum = 0;
                foreach (double v in samples) sum += v;
                return sum / samples.Count;
            }
        }

        public double Max
        {
            get
            {
                double max = double.NaN;
                foreach (double v in samples) if (double.IsNaN(max) || v > max) max = v;
                return max;
            }
        }

        /// <summary>Linear-interpolated percentile, p in [0, 100].</summary>
        public double Percentile(double p)
        {
            if (samples.Count == 0) return double.NaN;
            var sorted = new List<double>(samples);
            sorted.Sort();
            double rank = p / 100.0 * (sorted.Count - 1);
            int lo = (int)Math.Floor(rank), hi = (int)Math.Ceiling(rank);
            return sorted[lo] + (sorted[hi] - sorted[lo]) * (rank - lo);
        }
    }
}
```

```csharp
using Unity.Burst;
using Unity.Collections;
using Unity.Collections.LowLevel.Unsafe;
using Unity.Jobs;

namespace WAR2D.Spike
{
    /// <summary>
    /// Builds an integration field (cost to the nearest goal) over the tile grid. Straight steps cost 10,
    /// diagonals 14, diagonals may not cut a blocked corner. Dial's algorithm with a 16-bucket ring.
    /// </summary>
    [BurstCompile]
    public struct BuildIntegrationFieldJob : IJob
    {
        public const ushort Unreachable = ushort.MaxValue;
        private const int Straight = 10, Diagonal = 14, Ring = 16; // Ring > largest step

        public int Width, Height;
        [ReadOnly] public NativeArray<byte> Tiles;   // 0 = floor, anything else blocks
        [ReadOnly] public NativeArray<int> Goals;    // goal cell indices
        public NativeArray<ushort> Cost;             // output, length Width * Height

        public void Execute()
        {
            for (int i = 0; i < Cost.Length; i++) Cost[i] = Unreachable;

            var buckets = new NativeArray<UnsafeList<int>>(Ring, Allocator.Temp);
            for (int b = 0; b < Ring; b++) buckets[b] = new UnsafeList<int>(1024, Allocator.Temp);
            int pending = 0;

            for (int g = 0; g < Goals.Length; g++)
            {
                int goal = Goals[g];
                if (Tiles[goal] != 0 || Cost[goal] == 0) continue;
                Cost[goal] = 0;
                Push(ref buckets, 0, goal);
                pending++;
            }

            for (int c = 0; pending > 0; c++)
            {
                int slot = c & (Ring - 1);
                UnsafeList<int> list = buckets[slot]; // steps are 10 or 14, so nothing is added to this slot while we drain it
                for (int k = 0; k < list.Length; k++)
                {
                    int i = list[k];
                    pending--;
                    if (Cost[i] != c) continue; // stale entry, a cheaper route was found later
                    int x = i % Width, y = i / Width;
                    for (int dy = -1; dy <= 1; dy++)
                    for (int dx = -1; dx <= 1; dx++)
                    {
                        if (dx == 0 && dy == 0) continue;
                        int nx = x + dx, ny = y + dy;
                        if ((uint)nx >= (uint)Width || (uint)ny >= (uint)Height) continue;
                        int n = ny * Width + nx;
                        if (Tiles[n] != 0) continue;
                        bool diagonal = dx != 0 && dy != 0;
                        if (diagonal && (Tiles[y * Width + nx] != 0 || Tiles[ny * Width + x] != 0)) continue;
                        int next = c + (diagonal ? Diagonal : Straight);
                        if (next >= Unreachable || next >= Cost[n]) continue;
                        Cost[n] = (ushort)next;
                        Push(ref buckets, next & (Ring - 1), n);
                        pending++;
                    }
                }
                list.Clear();
                buckets[slot] = list;
            }

            for (int b = 0; b < Ring; b++) buckets[b].Dispose();
            buckets.Dispose();
        }

        private static void Push(ref NativeArray<UnsafeList<int>> buckets, int slot, int cell)
        {
            UnsafeList<int> l = buckets[slot];
            l.Add(cell);
            buckets[slot] = l;
        }
    }
}
```

```csharp
using Unity.Burst;
using Unity.Collections;
using Unity.Jobs;
using Unity.Mathematics;

namespace WAR2D.Spike
{
    /// <summary>Cell index per unit (cells are CellSize tiles square), clamped to the grid.</summary>
    [BurstCompile]
    public struct CellIndexJob : IJobParallelFor
    {
        [ReadOnly] public NativeArray<float2> Positions;
        public NativeArray<int> Cell;
        public float InvCellSize;
        public int CellsX, CellsY;

        public void Execute(int i)
        {
            int2 c = math.clamp((int2)math.floor(Positions[i] * InvCellSize), 0, new int2(CellsX - 1, CellsY - 1));
            Cell[i] = c.y * CellsX + c.x;
        }
    }

    /// <summary>Counting sort of units by cell: units of cell c are Sorted[CellStart[c] .. CellStart[c + 1]).</summary>
    [BurstCompile]
    public struct CountingSortJob : IJob
    {
        [ReadOnly] public NativeArray<int> Cell;
        public NativeArray<int> CellStart; // length cells + 1
        public NativeArray<int> Sorted;    // length units

        public void Execute()
        {
            for (int c = 0; c < CellStart.Length; c++) CellStart[c] = 0;
            for (int i = 0; i < Cell.Length; i++) CellStart[Cell[i] + 1]++;
            for (int c = 1; c < CellStart.Length; c++) CellStart[c] += CellStart[c - 1];
            var cursor = new NativeArray<int>(CellStart.Length - 1, Allocator.Temp);
            NativeArray<int>.Copy(CellStart, cursor, cursor.Length);
            for (int i = 0; i < Cell.Length; i++) Sorted[cursor[Cell[i]]++] = i;
            cursor.Dispose();
        }
    }

    /// <summary>
    /// Nearest living enemy within range, searched by 1 / Slice of the units each tick (staggered by index).
    /// Units not searched this tick keep their previous Target.
    /// </summary>
    [BurstCompile]
    public struct NearestEnemyJob : IJobParallelFor
    {
        [ReadOnly] public NativeArray<float2> Positions;
        [ReadOnly] public NativeArray<byte> Team;
        [ReadOnly] public NativeArray<float> Health;
        [ReadOnly] public NativeArray<float> RangeSq;
        [ReadOnly] public NativeArray<int> CellStart, Sorted;
        public float InvCellSize;
        public int CellsX, CellsY, SearchCells; // SearchCells = ceil(maxRange / CellSize)
        public int Tick, Slice;
        public NativeArray<int> Target;

        public void Execute(int i)
        {
            if (Slice > 1 && (i + Tick) % Slice != 0) return;
            if (Health[i] <= 0f) { Target[i] = -1; return; }

            float2 p = Positions[i];
            byte team = Team[i];
            float best = RangeSq[i];
            int bestIndex = -1;
            int2 c = (int2)math.floor(p * InvCellSize);
            int2 lo = math.max(c - SearchCells, 0);
            int2 hi = math.min(c + SearchCells, new int2(CellsX - 1, CellsY - 1));
            for (int cy = lo.y; cy <= hi.y; cy++)
            for (int cx = lo.x; cx <= hi.x; cx++)
            {
                int cell = cy * CellsX + cx;
                for (int k = CellStart[cell]; k < CellStart[cell + 1]; k++)
                {
                    int j = Sorted[k];
                    if (Team[j] == team || Health[j] <= 0f) continue;
                    float d = math.distancesq(p, Positions[j]);
                    if (d <= best) { best = d; bestIndex = j; }
                }
            }
            Target[i] = bestIndex;
        }
    }
}
```

- [ ] **Step 2: Implement `Shadowcast`.** This is Albert Ford's symmetric shadowcasting, made iterative (Burst-friendly) with exact integer slopes and limited to a circle:

```csharp
using Unity.Collections;
using Unity.Mathematics;

namespace WAR2D.Spike
{
    /// <summary>
    /// Symmetric shadowcasting (Albert Ford, 2020) with exact integer slopes, limited to a circle of the given radius.
    /// Marks visible tiles with 1. Blocking tiles are visible themselves but stop sight. Out-of-map counts as blocking.
    /// Writes only the value 1, so many casts may share one grid from parallel jobs.
    /// </summary>
    public static class Shadowcast
    {
        private struct Row { public int Depth, StartNum, StartDen, EndNum, EndDen; }

        public static void Cast(int2 origin, int radius, int width, int height,
                                in NativeArray<byte> tiles, ref NativeArray<byte> visible)
        {
            int radiusSq = radius * radius + radius; // a slightly rounder circle than r^2
            Mark(origin, width, height, ref visible);
            var stack = new NativeList<Row>(64, Allocator.Temp);
            for (int quadrant = 0; quadrant < 4; quadrant++)
            {
                stack.Add(new Row { Depth = 1, StartNum = -1, StartDen = 1, EndNum = 1, EndDen = 1 });
                while (stack.Length > 0)
                {
                    Row row = stack[stack.Length - 1];
                    stack.RemoveAt(stack.Length - 1);
                    if (row.Depth > radius) continue;

                    // round_ties_up(depth * start) and round_ties_down(depth * end), in integers
                    int minCol = FloorDiv(2 * row.Depth * row.StartNum + row.StartDen, 2 * row.StartDen);
                    int maxCol = CeilDiv(2 * row.Depth * row.EndNum - row.EndDen, 2 * row.EndDen);
                    int prev = -1; // -1 none yet, 0 floor, 1 wall
                    for (int col = minCol; col <= maxCol; col++)
                    {
                        int2 tile = Transform(quadrant, origin, row.Depth, col);
                        bool wall = IsBlocking(tile, width, height, tiles);
                        bool inCircle = row.Depth * row.Depth + col * col <= radiusSq;
                        if (inCircle && (wall || IsSymmetric(row, col))) Mark(tile, width, height, ref visible);
                        if (prev == 1 && !wall)
                        {
                            row.StartNum = 2 * col - 1;
                            row.StartDen = 2 * row.Depth;
                        }
                        if (prev == 0 && wall)
                        {
                            Row next = row;
                            next.Depth = row.Depth + 1;
                            next.EndNum = 2 * col - 1;
                            next.EndDen = 2 * row.Depth;
                            stack.Add(next);
                        }
                        prev = wall ? 1 : 0;
                    }
                    if (prev == 0)
                    {
                        Row next = row;
                        next.Depth = row.Depth + 1;
                        stack.Add(next);
                    }
                }
            }
            stack.Dispose();
        }

        private static bool IsSymmetric(Row row, int col) =>
            col * row.StartDen >= row.Depth * row.StartNum && col * row.EndDen <= row.Depth * row.EndNum;

        private static int2 Transform(int quadrant, int2 o, int depth, int col)
        {
            switch (quadrant)
            {
                // The four 90-degree quadrants around the origin; which one is called "north" doesn't matter.
                case 0: return new int2(o.x + col, o.y - depth);
                case 1: return new int2(o.x + depth, o.y + col);
                case 2: return new int2(o.x + col, o.y + depth);
                default: return new int2(o.x - depth, o.y + col);
            }
        }

        private static bool IsBlocking(int2 t, int width, int height, in NativeArray<byte> tiles) =>
            (uint)t.x >= (uint)width || (uint)t.y >= (uint)height || tiles[t.y * width + t.x] != 0;

        private static void Mark(int2 t, int width, int height, ref NativeArray<byte> visible)
        {
            if ((uint)t.x < (uint)width && (uint)t.y < (uint)height) visible[t.y * width + t.x] = 1;
        }

        private static int FloorDiv(int a, int b) => a >= 0 ? a / b : -((-a + b - 1) / b); // b > 0
        private static int CeilDiv(int a, int b) => -FloorDiv(-a, b);
    }
}
```

```hlsl
Shader "Spike/InstancedUnit"
{
    Properties { _MainTex ("Atlas", 2D) = "white" {} _UnitSize ("Unit size", Float) = 0.8 }
    SubShader
    {
        Tags { "RenderType"="Transparent" "Queue"="Transparent" "RenderPipeline"="UniversalPipeline" }
        Blend SrcAlpha OneMinusSrcAlpha
        ZWrite Off
        Cull Off
        Pass
        {
            HLSLPROGRAM
            #pragma vertex vert
            #pragma fragment frag
            #pragma target 4.5
            #include "Packages/com.unity.render-pipelines.universal/ShaderLibrary/Core.hlsl"

            struct UnitInstance { float2 position; float rotation; uint frame; uint color; float health; float scale; float pad; };
            StructuredBuffer<UnitInstance> _Instances;
            StructuredBuffer<float4> _FrameRects; // xy = uv min, zw = uv size
            TEXTURE2D(_MainTex);
            SAMPLER(sampler_MainTex);
            float _UnitSize;

            struct v2f { float4 pos : SV_POSITION; float2 uv : TEXCOORD0; half4 color : COLOR; };

            static const float2 Corners[6] =
            {
                float2(-0.5, -0.5), float2(0.5, -0.5), float2(0.5, 0.5),
                float2(-0.5, -0.5), float2(0.5, 0.5), float2(-0.5, 0.5)
            };

            v2f vert(uint vid : SV_VertexID, uint iid : SV_InstanceID)
            {
                UnitInstance u = _Instances[iid];
                float2 c = Corners[vid];
                float s, co;
                sincos(u.rotation, s, co);
                float2 local = float2(c.x * co - c.y * s, c.x * s + c.y * co) * _UnitSize * u.scale;
                v2f o;
                o.pos = TransformWorldToHClip(float3(u.position + local, 0));
                float4 r = _FrameRects[u.frame];
                o.uv = r.xy + (c + 0.5) * r.zw;
                o.color = half4((u.color & 255) / 255.0, ((u.color >> 8) & 255) / 255.0,
                                ((u.color >> 16) & 255) / 255.0, ((u.color >> 24) & 255) / 255.0);
                return o;
            }

            half4 frag(v2f i) : SV_Target
            {
                return SAMPLE_TEXTURE2D(_MainTex, sampler_MainTex, i.uv) * i.color;
            }
            ENDHLSL
        }
    }
}
```

### Task 9: Replication bandwidth with 8 simulated clients (row "Bandwidth per client")

Answers the question "is the hybrid model under 128 KB/s per client?" It has two stages. Stage A counts encoded bytes exactly, and it's the go/no-go number. Stage B pushes the same streams through real Mirror/KCP on loopback to check the transport carries them, and to measure the host CPU cost.

**Files:** `Assets/Spike/Net/VarInt.cs`, `SpikeMessages.cs`, `InterestSets.cs`, `ReplicationEncoder.cs`, `LoopbackSoak.cs`, `tools/spike-pcap.py`, `Assets/Spike/Tests/ReplicationTests.cs`

**Interfaces:**
- Produces `VarInt.Write/Read` (LEB128) and `ZigZag`.
- Produces `InterestSets`. Per client it holds a bitset over unit ids of what that client currently knows. The **only** input to the encoder is the per-client "allowed" set: all units of the client's team, plus enemy units on tiles its team's `Visible` grid marks. The encoder can't see anything else. This is the structural guarantee v0.5's leak tests will check, prototyped here.
- Produces `ReplicationEncoder.EncodeTick(clientIndex, NetworkWriter reliable, NetworkWriter unreliable)`.

**Message layouts** (all ids are delta-encoded varints against the previous id in the same message, and positions are quantised to 1/16 tile as `ushort`):

| Message | Channel | Layout |
|---|---|---|
| `MoveOrder` | reliable | `type(1) tick(varint) speedClass(1) count(varint)`, then per unit `idDelta(varint) waypointCount(varint) first(ushort×2, tile) rest(sbyte×2 per waypoint, escape 0x80 → ushort×2)` |
| `Correction` | unreliable, ≤ 1,194 B per message | `type(1) tick(varint) count(varint)`, then per unit `idDelta(varint) x(ushort) y(ushort) resumeWaypoint(varint)` |
| `Health` | reliable | `type(1) count(varint)`, then per unit `idDelta(varint) health(byte, % of max)` |
| `Enter` (spawn or became visible) | reliable | `type(1) count(varint)`, then per unit `idDelta(varint) unitType(1) owner(1) x(ushort) y(ushort) health(1)`, followed by its remaining route as in `MoveOrder` |
| `Leave` (death, or left vision) | reliable | `type(1) count(varint)`, then per unit `idDelta(varint) reason(1)` |
| `Explosion` | reliable | `type(1) count(varint)`, then per explosion `x(ushort) y(ushort)` |
| `FogDelta` | reliable | `type(1) count(varint)`, then the gaps between changed cell indices as varints (the client toggles each one) |

**Waypoints:** trace the unit's flow field from its tile to the goal and keep only the cells where the direction changes. Also record the waypoint count with a greedy line-of-sight smoothing pass, to see how much it saves.

**Corrections:** the server evaluates the same `PathFollower` function the client uses. It sends a correction when the actual position differs from the predicted one by more than 0.25 tiles, at most once every 2 ticks per unit. After a correction, the prediction restarts from the corrected point toward `resumeWaypoint`.
