# v0.8 "New Paint" Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace every placeholder sprite, tile, effect, icon and (missing) sound with one consistent pixel-art and chiptune set made by scripts in the repo. Also produce the **v0.7 art kit** (Builder, Digger, walls, bomb, blueprints), because v0.8 now ships **before** v0.7 and the art style decides how those look.

**Architecture:**
- **Generators, not hand-placed assets.** Pure C# generators in `Assets/Scripts/Art/` and `Assets/Scripts/Audio/` (runtime assembly, no `UnityEditor`, so EditMode tests reach them) write PNG and WAV sources. Thin editor wrappers in a new `WAR2D.Editor` assembly run them from a menu and import the output.
- **One manifest.** `ArtManifest` lists every sprite id (named exactly like its `UnitType` / `BuildingType` / `TileType` value, or a fixed string for effects and icons). Tests fail when an enum value has no art, so v0.7 can't add a type without art.
- **Atlases + team masks.** The importer packs frames into atlases with a parallel team-colour mask. The unit shader and a new sprite shader tint only masked pixels with the owner's palette colour.
- **Terrain** moves from one texel per tile (`MapView`) to an index texture plus a tile atlas sampled in a shader, with a flat-colour fallback when zoomed far out.
- **Audio** is client-only and fires only from data the client already receives, so it can't leak hidden information.

**Tech Stack:** Unity 6000.4.1f1, URP 17.4 (2D) incl. `PixelPerfectCamera`, Entities 6.4, Mirror 96, UI Toolkit, Unity Test Framework 1.6. Prototype (b) image tool: the Figma connector's image generation (`generate_image` / `weave_*`), or a tool the owner names.

**Spec:** [roadmap design spec](../specs/2026-10-05-war2d-roadmap-design.md) §7 (art and audio). Also read:
- [roadmap.md](../../roadmap.md) §3 v0.8 and v0.7, §4, §5
- [v0.7 Siege design](../specs/2026-10-10-v0.7-siege-design.md): Phases 3–7 define what the v0.7 art kit must cover
- [known-issues.md](../../known-issues.md): the v0.8 row ("every unit type draws with the Tank texture") is fixed in Task 7
- [v0.6 Figma record](../../ux/v0.6-figma.md): the UI skin (Task 12) extends this file's tokens

## Global Constraints

- Unity editor **6000.4.1f1**, open on the project. `tools/unity-compile.sh`, `tools/unity-test.sh EditMode`, `tools/unity-test.sh PlayMode`. **Both suites pass at the end of every task.**
- **Performance budget (roadmap §4):** client **≥ 60 fps** with 10,000 own units on screen; host tick ≤ 25 ms p95 at 80,000 units; ≤ 256 KB/s average per client. Tasks 7, 9 and 10 re-run `tools/perf-run.sh`.
- **One pixels-per-unit value for all art** (set in Task 5). Import settings: point filter, no compression, no mipmaps.
- **Every generator is deterministic:** same inputs and seed → byte-identical output. Generated outputs are committed as assets (spec §7.4).
- **Owner gates:** method choice (Task 4), style guide (Task 5), UI skin in Figma (Task 12, [Figma approval before UI]), and owner review of every art PR before merge (spec §7.3).
- **No new client messages for art or audio.** Anything drawn or played comes from data the client already has; `LeakTests` keep passing.
- Scene and asset changes go through the live editor (`unity command ...`), never hand-edited YAML. Don't edit vendored code.
- Every asset made with an AI image tool is logged in `docs/art/ai-content.md` (spec §7.5; the Steam survey itself is v0.9).
- Commits never carry co-author or AI attribution. Branch `release/v0.8` from `main` once v0.6 is merged; one PR per task group into it.
