# v0.14 AI opponents Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. This plan lists each task's files, steps and tests; write the code against the files as they are when you start (read them first).
> Project rules that apply to every task: compile with `tools/unity-compile.sh` while working; run **both** suites (`tools/unity-test.sh EditMode`, `tools/unity-test.sh PlayMode`) **once at the end of the whole plan** (the owner's preference, 2026-10-16), not after every edit. Commit only when the owner has asked for it, on `release/v0.14`, never from `main`, and **never add a co-author or AI attribution line** (`CLAUDE.md`). Don't hand-edit `.csproj`/`.slnx`, scene, prefab or `.asset` files. Don't edit vendored code. Restart the editor after changing `SimData`'s fields, before running tests.

**Goal:** AI players added in the lobby (Easy, Normal, Hard; Rusher, Turtle, Expander, Balanced or Random; callsign, colour, team), playing the whole game on the server through the same validated actions as a player and seeing only their team's view; lobby Visibility (Public, Friends, Private); pause in one-human matches; the dev bots replaced by AI seats.

**Spec:** [2026-10-23-v0.14-ai-opponents-design.md](../specs/2026-10-23-v0.14-ai-opponents-design.md) (every rule, number and open decision). Parent: [roadmap](../../roadmap.md) §2 v0.14. HUD: `docs/ux/v0.14-figma.md` (written in Task 0).

**Written before v0.13 is built (owner's request, 2026-10-23).** The AI plays the v0.13 Gun turret and Jammer, and v0.13 changes combat, vision and attack events. Before starting, re-read this plan against the merged v0.13 code and fix any file or type it names that moved.

## Global constraints

- **No cheating, by construction.** AI code (`Assets/Scripts/Ai/`, namespace `WAR2D.Ai`) reads only its `TeamView` and acts only through `PlayerActions`. It never touches `SimData`, `MapStore`, `SimCommandQueue`, another player's `ServerPlayer`, or ECS entities. Put it in its own assembly definition (`WAR2D.Ai`) whose references make the forbidden types unreachable where practical, and keep a test that fails if the assembly references them.
- Server-authoritative as always; main-thread code never touches `Unit` entities or `SimData` arrays between ticks: the `TeamView` is built from `SimContext.Settled`.
- Every new or changed `[Command]` (lobby AI slots, Visibility, pause): `requiresAuthority = false`, `NetworkConnectionToClient sender = null`, `CommandGate.Allow` first with a budget entry, host-only where the spec says, value checks; fuzz tests for each.
- Hidden information never leaves the server: a Random style is resolved on the server and sent only at GameOver; `LeakTests` keep passing and `AiLeakTests` are added.
- Every AI number in `GameConfig.xml` (`<Ai>`), parsed strictly. No hard-coded tuning in the brain.
- Any HUD change beyond the approved frames goes back through Figma first.
- Perf budget: the §4.1 gate unchanged with Scripted seats; with 7 Hard AIs, AI thinking ≤ 2 ms main-thread p95 (`perf.part.ai`) and the tick still ≤ 25 ms p95. Results in `docs/perf/v0.14/`.

### Task 7: Playing the game (managers)

**Files:** `Ai/Managers/Opening.cs`, `Economy.cs`, `Builder.cs`, `Production.cs`, `Scouting.cs`, `Army.cs`, `Ai/Placement.cs`, `Ai/StrengthEstimate.cs`, tests. Build in this order, each playable before the next: an AI that only places its HQ and mines, then builds and produces, then fights.

- [ ] **Opening:** score dealt options (gems and rich fields in reach, open ground, teammates' picks), place the HQ through `PlayerActions` before the pick deadline; run the style's opening build order.
- [ ] **Placement:** a search over explored free ground near a centre that returns a spot `PlacementRules` accepts, or none; spread over thinks for large searches; Miners only facing gems.
- [ ] **Economy:** Builders target by difficulty; Miners on gems; expansions on the v0.11 region graph by style and difficulty; upkeep check before every production or build (Normal and Hard never go unpaid).
- [ ] **Builder:** blueprints for producers, Radar, defences at chokepoints between base and known enemies (turret, Jammer, bombs, walls, by style); assign Builders; repair.
- [ ] **Production:** producer type and queue from the style's army mix shifted by counters (spec §5.5 by difficulty); rallies at the army's gathering point.
- [ ] **Scouting:** a scout route over unexplored start sites and expansions; re-scout known bases.
- [ ] **Army:** squads; defend on Under-attack (after the reaction delay); attack when `StrengthEstimate` (from what it has seen) favours it; retreat (Normal, Hard); focus fire and keep Artillery and Snipers behind the front (Hard); Diggers past walls on its route (Hard); Suicide bombers at clumps and walls (Detonate); Turtle holds chokes.
- [ ] Tests (EditMode, scripted worlds): HQ placed inside an option; placement always legal; Normal never unpaid over 5 simulated minutes; counters chosen from seen units; retreat when outnumbered; attack target is a known (seen) building, never an unseen one.

### Task 8: Diplomacy and conceding

**Files:** `Ai/Managers/DiplomacyManager.cs`, `Ai/Managers/Concede.cs`, tests.
