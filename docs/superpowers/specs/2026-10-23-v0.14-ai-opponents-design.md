# v0.14 AI opponents: Design

**Status:** written 2026-10-23 from the owner's answers (§13); **not yet reviewed by the owner**. Numbers are starting values to tune in play. The owner hasn't seen §5 (the brain's structure), §6's difficulty numbers, §7's diplomacy rules or §9's pause audit in detail; the open decisions are in §14.
**Parent:** [roadmap](../../roadmap.md) §2 v0.14. **Store:** [store page plan](2026-10-19-store-page-design.md) §6 (Single-player goes on the page once this ships).
**Plan:** [2026-10-23-v0.14-ai-opponents.md](../plans/2026-10-23-v0.14-ai-opponents.md).

## 1. Goal

Someone to play against when nobody else is online, before the Steam Early Access launch:

1. **AI players in the lobby**: the host adds AI slots, each with a difficulty (Easy, Normal, Hard), a play style, a colour and a team, like a human player.
2. **An AI that plays the whole game**: it places its HQ in one of its dealt start options, builds an economy, expands, builds the whole roster and the v0.13 defences, scouts, attacks, defends, and reacts to diplomacy.
3. **Fair by construction**: it runs on the server, sees only what its team sees, and acts only through the same validated actions a player's commands use. No difficulty cheats (owner, 2026-10-23).
4. **Single-player and co-op through the lobby**: a Private lobby with AI slots is Single-player; humans on a team with AIs is co-op. There is no separate Single-player mode (owner).

**Out of scope:** a campaign or scenarios, the tutorial, AI chat or taunts, giving the AI orders ("takes requests"), AI on clients, machine-learned play, replacing a disconnected human with an AI.

## 2. Lobby

### 2.1 AI slots

- The host has an **Add AI** button under the player list (shown while the lobby has a free seat; humans and AIs together are at most `LobbyRules.MaxPlayers`, 8).
- An AI row shows: a generated **callsign** (§2.3) with an **AI tag** and the difficulty, a **difficulty** dropdown (Easy, Normal, Hard; default Normal), a **style** dropdown (Random, Rusher, Turtle, Expander, Balanced; default Random; §5.6), its **colour** (the first unused one; the host can change it), its **team** in Teams mode (the host sets it the same way they cycle anyone's team), and **Remove**.
- An AI is always ready. Changing an AI's row clears everyone's ready, like any settings change.
- Only the server owner (host) adds, changes or removes AIs. A Random style is resolved by the server at match start and never sent to clients (nobody learns it, not even the host, until the end screen shows it).
- **Start match** rules are unchanged: every human ready and at least two teams. One human and one AI is a valid match.
- If the server owner passes to another human, the AI slots stay and the new owner can edit them.

### 2.2 Lobby visibility

A new host setting, **Visibility**: Public, Friends (today's behaviour, the default), Private.

- **Public / Friends:** a Steam lobby of that type (`ISteamBackend.CreateLobby` takes the type; `SteamworksBackend` maps it to `k_ELobbyTypePublic` / `k_ELobbyTypeFriendsOnly`).
- **Private:** no Steam lobby is created and the server accepts no connection but the host's own. Invites and the Direct block are hidden. **Private works without Steam running** (the host already falls back to KCP-only hosting; Private additionally refuses every remote connection). A Private lobby with AIs is Single-player.
- Changing Visibility in the lobby opens or closes the Steam lobby; going Private while other humans are connected is refused with a hint ("Remove the other players first").

### 2.3 Names

Each AI gets a **military callsign** from a list in `GameConfig.xml` (`<Ai><Callsigns>`, e.g. "Cmdr. Vasquez", "Maj. Okafor"), unique within the match, drawn with the lobby seed so a reroll changes them. The UI shows the callsign plus an AI tag and the difficulty ("Cmdr. Vasquez · AI · Hard") everywhere a player name appears: lobby, top bar, diplomacy panel, gift dialog, alerts, end screen, replays.

## 3. AI players on the server

- `GameCore.Bots` (connectionless `ServerPlayer`s, dev only today) becomes **`GameCore.AiPlayers`**: a `ServerPlayer` with no connection plus an `AiSeat` (difficulty, style, callsign, brain). It counts in the player order, the player count, teams, diplomacy, upkeep, income, win/loss and statistics exactly like a human.
- **Owner ids:** an AI's owner id comes from a reserved range that can never be a Mirror `netId` (the top of the `int` range, as the dev bots' `1000001+` does today, checked against Mirror's allocator in a test).
- **Clients see AI players as players.** Each AI gets a server-owned `ClientPlayer` object (no connection, `isAi` SyncVar, callsign as its nickname), so the top bar, diplomacy panel, gift dialog, alerts and end screen work unchanged. This is one networked object per *player*, not per entity, so the "no networked GameObjects per entity" rule holds. It fixes the known issue "Bots look eliminated in the HUD". Its `TargetRpc`s have no connection to go to and are skipped; the AI reads the same facts from its view (§4). (Alternative in §14 O1.)
- **Dev bots** (perf harness, tests) become AI players with the dev-only difficulty **Scripted**: a seat with no brain that the harness drives as today (`DevApi.Allowed`, refused without `-perf`). There is one kind of non-human player.

## 4. What the AI may know: the team view

The AI never reads `SimData`, `MapStore` or another player's `ServerPlayer` directly. Each think it gets a **`TeamView`**, built from the same rules replication uses for a client of its owner:

| Fact | Source and rule (same as a client's) |
| --- | --- |
| Own units: id, type, position, health, order and stance | Own team's units (`ReplicationService` interest: own units always) |
| Teammates' and allies' units | Units on cells the owner's grid sees now (shared vision included) |
| Enemy units | Only on fog cells the owner's grid sees **now** (`SimVisionSystem`), the same predicate `InterestSets` uses |
| Buildings | `BuildingInterest` for the owner: own, seen now, and **last-seen ghosts** (a destroyed ghost stays until its spot is seen again) |
| Fog | The owner's grid: unexplored / explored / visible |
| Terrain | The generated map (the client gets it from the seed too) plus wall and dig changes only for cells the owner's grid has seen (`TerrainMessages` rule) |
| Own resources, income, upkeep | The owner's `ServerPlayer` (what `ClientPlayer.TargetResources` sends) |
| Alerts | The alerts `AlertService` would send this owner (under attack, Radar pings, gifts received) |
| Attack events | Those the owner's client would receive: the attacker only if the client may know it, the target named by `MayKnowTarget` |
| Diplomacy | Its own row, and who shares vision with it (what `ClientPlayer.TargetDiplomacy` sends); never another player's row |
| Start options | Its own dealt options only (and its teammates', as a human teammate sees them) |
| Match | `GameCore.CurrentState`, settings, player list with teams (public lobby information) |

- **One predicate, two users.** The interest checks the encoder uses are pulled into shared static functions; `TeamViewBuilder` and the encoder both call them, so the AI can't see more than a client by drifting from it.
- **Built on the settled world.** `TeamViewBuilder` runs from `SimContext.Settled` (main-thread reads are safe there), only for the AI(s) whose think is due this tick, and copies into the AI's own buffers (reused, no per-think garbage).
- **Bomb and Jammer rules hold automatically:** hidden bombs never reach it unless its side may know them, and a jammed cell is simply not visible on its grid (v0.13).
- **Proof:** `AiLeakTests` (EditMode, world-level) put an enemy unit, building, bomb, wall change and explosion where the AI's side can't see, and assert none of them is in its `TeamView`; then reveal each and assert it appears. A PlayMode test compares an AI's `TeamView` with a real human teammate's client stores on the same tick (same team, shared vision: the visible sets must match).

## 5. How the AI plays

### 5.1 Acting like a player

- The body of every player `[Command]` the AI needs is moved into a server-side **`PlayerActions`** method taking an owner id (`PlaceHq`, `PlaceBuilding`, `Order`, `DigArea`, `SetProduction`, `ChangeQueues`, `SetRally`, `SetAttack`, `SetShareVision`, `Gift`, `Surrender`, `Detonate`, squads). Each Command keeps its `CommandGate.Allow` and `TryActingOwner` and then calls the action, so **a client and the AI pass the same validation**. The AI never enqueues `SimCommand`s itself.
- Instead of the network budget, an AI's actions draw on an **action budget** (actions per minute by difficulty, §6), so a Hard AI can't out-click a person by orders of magnitude.

### 5.2 Thinking

- An `AiDirector` (server only, `Assets/Scripts/Ai/`, namespace `WAR2D.Ai`) runs only in *PlacingHQ* and *Playing* and gives each AI a think every `ThinkSeconds` (by difficulty), staggered so at most one AI thinks per tick.
- **Budget:** all AI thinking together stays under **2 ms of main-thread time per tick p95** with 7 Hard AIs at the perf gate's scale. Heavy searches (placement, expansion scoring) are spread over several thinks; pathing questions use the existing sector graph, never a new flood fill per think.
- **Reaction delay:** an event (an alert, a newly seen enemy army) is acted on only after `ReactionSeconds` (by difficulty), so Easy reacts late and Hard reacts quickly.

### 5.3 Structure

A blackboard (the `TeamView` plus the AI's memory: known enemy bases, last-seen army sizes and composition, threats, its plans) and managers that each propose actions with a priority; the director spends the action budget on the highest first.

| Manager | Job |
| --- | --- |
| **Opening** | Picks a start option (score: gems and rich fields near it, open ground, distance to known teammates' picks) and places the HQ; runs the style's build order for the first minutes. |
| **Economy** | Keeps a target number of Builders; places Miners facing gems (`PlacementRules`); expands to rich fields at expansions (region graph from v0.11); never lets upkeep go unpaid on Normal and Hard (it pauses production and builds Miners first). |
| **Builder** | Places blueprints on explored free ground near its base or expansion (a placement search over `PlacementRules`), assigns Builders to blueprints, repairs, finishes walls; defences (turrets, Jammers, bombs) at chokepoints between its base and known enemies. |
| **Production** | Chooses each producer's unit type and queue from the army composition target (style, counters, §5.5) and resources; sets rallies. |
| **Scouting** | Sends a Scout (or the first unit) to likely start sites and expansions; re-scouts known bases; keeps a Radar where the style wants one. |
| **Army** | Groups units into squads; defends when an Under-attack alert arrives (after the reaction delay); attacks known enemy buildings or last-seen armies when its army is strong enough (estimated from what it has seen, never from hidden facts); retreats from a losing fight (Normal, Hard); Diggers tunnel past walls blocking its route (Hard); Suicide bombers at clumps and walls; Artillery and Snipers behind the front line. |
| **Diplomacy** | §7. |
| **Concede** | §8. |

### 5.4 Placement and pathing

- Placement uses the same rules a client's preview does (`PlacementRules`, explored ground only, the HQ inside a dealt option).
- Attack targets and routes are chosen on the region graph and sector graph; units are then ordered with ordinary Move / AttackMove orders, so they path exactly like a player's.

### 5.5 Counters

Easy builds its style's fixed mix. Normal shifts the mix toward counters of what it has seen (Heavies seen → more Snipers and Artillery; massed light units → Flamethrowers and turrets). Hard also counters what it hasn't seen yet but expects from the enemy buildings it has seen (a Heavy Factory ghost → anti-Heavy).

### 5.6 Styles

Every style uses the same managers with different weights (`GameConfig.xml`, `<AiStyle>`):

| Style | Plays like |
| --- | --- |
| **Rusher** | Early Barracks, Scouts and Tanks, attacks early and often, expands late. |
| **Turtle** | Walls, turrets, Jammers and bombs at its chokepoints; a big Heavy and Artillery army later. |
| **Expander** | Takes expansions early, more Miners, a mid-game army. |
| **Balanced** | A bit of each; the default when Random picks. |

The host picks the style per AI slot, or Random (resolved privately by the server, §2.1).

## 6. Difficulty

No difficulty gets more resources, vision or speed (owner, 2026-10-23). Difficulty only changes how well the AI plays (starting values):

| | Easy | Normal | Hard |
| --- | --- | --- | --- |
| `ThinkSeconds` | 1.0 | 0.5 | 0.25 |
| Actions per minute | 30 | 80 | 200 |
| `ReactionSeconds` | 6 | 2 | 0.5 |
| Builders target | low | full | full, plus extra for expansions |
| Expands | late, one | on time | early, as the style wants |
| Upkeep discipline | may go unpaid | never unpaid | never unpaid |
| Counters (§5.5) | none | seen units | seen units and buildings |
| Retreat, focus fire, keep long range units back | no | retreat | all |
| Scouting | once | regular | regular, plus Radar |
| Uses Diggers, bombers, bombs, Jammers | rarely | as the style wants | as the style wants, at chokepoints |

**Target (exit criterion, owner):** over a seed batch on every map size, Hard beats Normal in ≥ 80% of 1v1 games and Normal beats Easy in ≥ 80%. How hard each level feels to a person is tuned in the owner's playtests.

## 7. Diplomacy (owner: the AI reacts to it)

Only when the match has Diplomacy on. The AI starts from the lobby teams like everyone. It knows only what a player knows: its own row, who shares vision with it, and who it sees attacking its things (attack events and alerts).

- **Teammates:** it never stops sharing vision with or starts attacking a teammate.
- **Peace:** a non-teammate who **shares vision with the AI** and **hasn't hit anything of the AI's for `PeaceSeconds`** (60 s) is offered peace: the AI stops attacking them and shares vision back. Whether it accepts depends on difficulty: Easy always; Normal unless it is clearly winning against them; Hard only when it is losing against them or both are fighting a third player.
- **Betrayal:** any hit from a player it is at peace with (seen on an attack event or an Under-attack alert naming them) makes it attack them again and stop sharing at once, and it refuses peace from them for `GrudgeSeconds` (180 s).
- **Gifts:** the AI gifts part of its surplus to teammates (§14 O5), within the normal gifting rules. A gift received from a non-teammate counts as a peace signal (it shortens `PeaceSeconds` by half; open decision O6).
- Win rules are unchanged: if every survivor is at peace, they win together. So a person can win with peace, but a Hard AI that is winning won't take it.

## 8. Conceding (owner: surrenders when hopeless)

After `ConcedeMinMinutes` (10), an AI surrenders, through the same Surrender action a player uses (eliminated exactly as losing its HQ), when for `ConcedeSeconds` (60) both hold:

- it has no producer able to make an attacking unit and no Builder, or it can't afford one with its resources plus a minute of income; **and**
- the strength it has (army and buildings, by cost) is below `ConcedeRatio` (10%) of the strongest enemy force it has seen in the last 2 minutes.

Easy, Normal and Hard all concede. An AI never concedes while a teammate is still alive and holding (so co-op partners aren't abandoned); it fights to the end instead.

## 9. Pause (owner: pause only)

- When **exactly one human is connected** (the host; AIs don't count) the in-match menu (Esc) **pauses the match** while it's open, and Resume unpauses. With two or more humans nothing pauses, as today. No speed control.
- The pause uses `SimPause` (today dev-only) through a new server-side `MatchPause` that dev pause also goes through. While paused: the tick doesn't run, the building systems are frozen (`SimPause.Frozen`), and every **match timer** stops: upkeep and income seconds, the HQ pick deadline, the countdown, production progress, diplomacy and gift cooldowns, alert cooldowns, AI thinking, win/loss checks. Timers that read wall time today move to a match clock that only advances while unpaused (the plan's Task 9 audits them).
- The client shows "Paused" in the menu; the recorder doesn't record paused time (the replay plays straight through).

## 10. HUD (Figma first)

Lobby: Add AI button, AI rows (callsign, AI tag, difficulty and style dropdowns, colour, team, Remove), the Visibility selector, the Private hint. In match: the AI tag on the top bar, diplomacy panel, gift dialog and alerts; the in-match menu's Paused state. End screen: the AI tag and each AI's style and difficulty. Nothing is built before the owner approves the frames.

## 12. Testing and performance

- **EditMode:** start-option scoring and HQ placement; building placement search (always a legal spot or none); the economy manager never goes unpaid on Normal/Hard in a scripted world; production picks counters (§5.5); the action budget; the diplomacy reactor (peace, refusal by difficulty, betrayal, grudge, teammates never attacked); the concede rule (and never while a teammate holds); Random style never reaches a client; lobby AI rows (add, change, remove, colours, teams, seat limit; only the host); Visibility (Private refuses remote connections; works with the fake Steam backend off); config parsing; fuzz tests for the new lobby commands.
- **AiLeakTests:** §4's proof. Plus: every AI action goes through `PlayerActions` (a test that the AI assembly references no `SimCommandQueue`).
- **PlayMode:** a Private match, one human vs one Easy AI: the AI places its HQ, builds Miners, a producer and an army, and attacks within the time a test allows (with the dev tick fast-forward). Co-op: a human and a Normal AI vs a Normal AI. Pause in a one-human match stops the tick and every timer; with two humans the menu doesn't pause.
- **AI vs AI batch:** `tools/ai-bench.sh` (control API, dev build, `-perf`, the tick unthrottled) plays N seeds per map size (256, 512, 1024) per pairing and reports winners and match lengths into `docs/perf/v0.14/ai-bench.md`. Exit: every match finishes (a win, or a draw at a time cap counts as a failure to fix) and the §6 win rates hold.
- **Performance:** the perf gate's 7 bots are Scripted AI seats (load unchanged); a second gate run replaces them with 7 Hard AIs on a 1024 map and must meet the budget with AI thinking measured on its own (`perf.part.ai`, ≤ 2 ms p95).

## 13. Decisions (owner, 2026-10-23)

| Topic | Decision |
| --- | --- |
| Difficulties | Easy, Normal, Hard |
| Cheating | Never: no fog cheating, no resource bonus at any level |
| Single-player | Through the lobby only (a Private lobby with AIs); no separate main-menu mode |
| AI's view | A team-view snapshot built from the same interest rules replication uses |
| Co-op teammate | An independent ally: plays its own game, shares vision, joins fights; humans don't give it orders |
| Diplomacy | The AI reacts to diplomacy (§7) |
| Styles | Rusher, Turtle, Expander, Balanced; the host picks per slot, or Random |
| Pause / speed | Pause only, when one human is connected; no speed control |
| Dev bots | Become AI players (a dev-only Scripted seat for the perf harness) |
| Lobby visibility | A host setting: Public, Friends, Private |
| Strength target | Hard beats Normal and Normal beats Easy in ≥ 80% of AI-vs-AI games |
| Conceding | The AI surrenders when hopeless (§8) |
| Names | Generated military callsigns, with an AI tag and the difficulty |
