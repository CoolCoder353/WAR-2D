# v0.19 Steady: Design

**Status:** written 2026-11-06 from the owner's choices in that day's planning session and approved by the owner the same day ("v0.19 looks fine"). Unlike the earlier specs this one describes work that is **already built**: it records what v0.19 contains, what is still unchecked, and what it takes to ship. Nothing new is added to it. The branch, with the playtest fixes, was merged to `main` in PR 44 (2026-11-06), so §4's first and last steps are done and the checks run on `main`'s code.
**Parent:** [roadmap](../../roadmap.md) §2 v0.19. **No Figma brief:** no frame was drawn for this work (see §5).

Ship the work built on the unstable branch since v0.18, finished and checked, as one release:

The shell is still only a picture: the damage lands when the Artillery fires. v0.20 makes it real.

### 2.5 Lobby

The Quick setup buttons and the board's help lines are gone, the whole card drags (lifted above the lobby while it moves), the map preview keeps the map square, and the command card's Dig, Detonate and Wall hint lines are removed (2026-11-06 playtest).

### 2.6 Under the hood

Cheaper ticks with the same results (a seat grid for formation slots, a `CellOwners` mask for target search, reach regions kept across terrain changes, Burst jobs for wall pushes and idle-Builder searches, replication encoding each client as soon as its data is ready; round 2), messages kept under the transport's caps (Health and fog snapshots split by size, building batches stop before overflow, `Summary/MaxPoints` 80; PR 39 and round 3), and the bug fixes in PR 39, PR 30 and the round-2 and round-3 lists.

## 4. What it takes to ship

In this order:

1. ~~**Commit the 2026-11-06 playtest fixes** and merge the branch.~~ Done: merged to `main` in PR 44 (2026-11-06), with a follow-up (waiting blueprints count against the building cap).
2. **Branch `release/v0.19`** from `main`, and set the versions (§3).
3. **Both suites pass** through the live editor. Last run (round 3): EditMode 1482/1482; PlayMode 97/98, the miss being `PerformanceTests.MinimapRedrawAtTenThousandOwnUnitsIsUnderOneMillisecond` at 1.0065 ms (it passed alone). The playtest fixes add `PhantomBlueprintPlayModeTests`, `BuilderCrowdTests` and `MoveJitterTests`; run both suites again with them in.
4. **Perf gate** (`tools/perf-run.sh`, Linux release build): main tick p95 at or under the new **28 ms** (round 3 measured 26.3 ms), bandwidth under 256 KB/s average. Two things never measured on a Linux build:
   - **Client frame time** at 10,000 own units on screen with the turret layer and the 4096×2048 atlases (PR 41).
   - **The record stream:** PR 30 raised it from about 505 to about 900 KB/s on a Windows build, cause unknown. Measure it; if it is still that high, find out why or log it in `known-issues.md`.
5. **`ai-bench` check** (`tools/ai-bench.sh --brief`): the difficulty ladder still holds. Closest-target Attack-moves (PR 33), own-speed Attack-moves and the new idle-Builder rule change how AI armies and economies play, though no balance number moved.
6. **Live checks** through the control API of the three playtest reports not reproduced in tests (known-issues, 2026-11-06): the production queue count with several producers, units jumping back and forth while moving (expected fixed by the half-tile routes), Builders standing idle instead of building. Each one is fixed or logged.
7. **Code and security review** of the whole branch against `main`, then a **full match on Linux** (this also stands in for the v0.16 to v0.18 matches the last roadmap left to play).
8. **Merge** `release/v0.19` (the version bump and anything the checks fix) into `main`. The code itself is already there (PR 44), and no PR from the unstable work is still open.
