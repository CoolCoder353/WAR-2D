# v0.17 Heartland: Design

**Status:** written 2026-11-01 from the owner's choices in that day's planning session; **approved by the owner on 2026-11-01** with the default open decisions. Numbers are starting values to tune in play. Not started; the implementation plan is written when v0.17 starts, after v0.16.
**Parent:** [roadmap](../../roadmap.md) §2 v0.17.

## 1. Goal

Give every map a middle worth fighting over: a **rich gem** tile, found only in the central areas, that a Miner mines for **2.5 times** the ordinary rate, **for good** (owner, 2026-11-01: "dense resources at the middle of maps", as a richer gem type that never runs out).

Today the start sites have a gem vein each, expansions have rich fields of ordinary gems (`<Map><ExpansionGemTiles>` 30), and central areas have rock outcrops but few gems. After v0.17 the central areas hold the best income on the map, away from every start site, so holding the middle is a real strategic choice and armies meet there.

**Out of scope:** gems that run out, any other new resource, a new building to mine it, changes to ordinary gems or expansions.

## 2. Rules

- **Tile:** `TileType.RichGem`, a gem in the rock face like an ordinary gem: solid, opaque, not walkable, never built on.
- **Mining:** a Miner facing a rich gem earns `<Resources><MiningRate>` × `<Resources><RichGemMultiplier>` (10 × 2.5 = **25/s**), endless, by the same once-a-second payout in `ResourceSystem`. Placement allows a Miner facing either kind (`MinerRules.Produces`). Everything else about Miners is unchanged (cost, health, upkeep, facing, `R` to rotate).
- **Digging:** a Digger can dig a rich gem like any gem tile; it pays `<Siege><RichGemPayout>` (375, 2.5 × `GemPayout`) once and the tile becomes ground for good, stopping any Miner on it (open decision D1).
- **Sight and fog:** as an ordinary gem. A client learns a rich gem where it learns any tile: it is part of the generated map every client regenerates from the seed (the map is public, as today; the generator already places ordinary gems that way).
- **End screen:** `MatchStats.Mined` counts it like any mining.

## 3. The generator

- `RegionMapGenerator`, after the ordinary gems: in every **central area** (`RegionKind.Central`), grow rich-gem veins on rock tiles that face floor, `<Map><CentralRichGemTiles>` per layout size (`8 16 24 32` for 128/256/512/1024), in 2 to 4 clusters per area so more than one side of the area is worth holding. Veins grow from rock faces inside the area's radius, never on the border, never within `<Map><RichMinStartDistance>` (0.15 of the map size, by lane distance) of a start site, and never in a lane's chokepoint.
- If a map has no central area far enough from every start site (small maps, unlucky seeds), the central area that is farthest from its nearest start site gets them; there is always at least one rich field.
- Ordinary gems in central areas stay as they are (few).
- **Fairness tests** grow by one check: every start site's lane distance to the nearest rich field lies within the same band the expansions use, so no start is beside the prize. The existing 1,000-seed tests at every map size run with it.
- Every seed's map and hash change (as v0.11 did); recordings made before v0.17 are refused by the replay player's version check (`ReplayPlayer`, "recorded with version …"), as for any new version.

## 4. Client

- **Art:** `RenderGen` draws a rich-gem tile set on the 47 blob shapes rock and gems use since 2026-10-31 (`RenderGen.RockShapes`, `TileAutotile.Corners`), with larger crystals in a brighter, warmer colour than ordinary gems, (the terrain shader has no tile animation, so no glint in the tile itself; the Miner glint below supplies the sparkle). Registered in `Editor/ArtBuild.cs`, built by `WAR-2D/Art/Build all`. `MapView` and `TileAutotile` get the new kind; it autotiles with rock and ordinary gems as one solid mass.
- **Minimap:** its own colour, brighter than ordinary gems, on explored cells.
- **Hover card and placement:** a Miner's hover card says "Mining rich gem: 25/s" (or "Mining: 10/s"); the placement preview of a Miner facing a rich gem says "Rich gem: 25/s". A small Figma frame for these two lines and the minimap colour, approved before they are built (the HUD rule).
- **Polish:** the Miner glint (polish item I) plays on rich gems too, in the rich colour.

## 5. The AI

- **Start options** (`OpeningManager`): a rich tile counts `RichGemMultiplier` ordinary gems in `OptionGemWeight` scoring (rare near starts by construction, so this mostly matters on small maps).
- **Expansions** (`EconomyManager`): central areas with rich gems become expansion candidates, scored by income (25 per Miner slot) against distance and known danger; the AI expands into the middle when its policy's timing and defence allow, and builds its defences there (`DefenceStart`, `HomeTurrets` rules apply to a claimed central area as to an expansion).
- **Targets** (`ArmyManager.ScoreTarget`): an enemy Miner's worth adds `MinerIncomeValue` × its payout ratio, so a rich Miner is a bigger target; a raid prefers them.
- **Bench:** `tools/ai-bench.sh --brief 16` before and after on the same seeds; the difficulty ladder must hold (Hard beats Normal, Normal beats Easy, as in the 2026-10-30 runs). If the middle makes games end faster on 1024 (the D9 caps), note it.


## 7. Code that changes

- `TileType.RichGem = 6`, added after `WallBlueprint` so existing values keep their numbers. Every `TileRules` query gets a case (`IsFloor` false, solid, opaque); `TileRules.MayChange` admits it (digging turns it to ground); `TerrainCodec.Apply`'s type bound becomes the new highest type; `NoPlaceholderArtTests` covers the new art.
- `MinerRules.Produces` takes either gem; a new `MinerRules.RateOf(TileType)` returns the multiplier (1 or `RichGemMultiplier`), used by `ResourceSystem` and the client's hover card and placement preview.
- `SimDigSystem` pays `RichGemPayout` for a rich gem.
- `RegionMapGenerator` (§3), `MapStore.Hash` unchanged in form (it hashes the new values).
- The AI's view already carries the tiles (`TeamView.Tiles`); the managers in §5.

## 8. Wire and version

A new tile value travels in terrain batches and the map, so `GameVersion.Protocol` becomes 17 and `bundleVersion` 0.17.0 (v0.16 takes 16).

## 9. Testing and performance

- **EditMode:** `TileRules` for the new kind; the codec accepts it and still refuses anything higher; `MinerRules` rate; a Miner on a rich gem earns 25/s (`ResourceSystem` test) and placement allows it; dig payout; generator: rich tiles only in central areas, the start-distance rule, the fallback area, fairness on 1,000 seeds at every size, determinism (same seed, same map); AI scoring tests in `AiSandbox` (a rich expansion beats an ordinary one at the same distance; a rich Miner scores higher as a target); `LeakTests` and `AiLeakTests` unchanged.
- **PlayMode:** a hosted match on a seed with a rich field: a Miner placed on it earns 25/s.
- **Perf:** `tools/perf-run.sh` on the new layout (the generator changes where the perf harness's armies meet).
- **In a running match** through the control API: screenshots of a rich field at close and far zoom, and on the minimap.
