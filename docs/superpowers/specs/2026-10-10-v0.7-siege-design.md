# v0.7 Siege — Design

**Status:** approved in brainstorming with the owner on 2026-10-10; awaiting written-spec review.
**Parent:** [roadmap](../../roadmap.md) §3 (v0.7) and the [roadmap design spec](2026-10-05-war2d-roadmap-design.md). Where this document differs from the parent, this document wins for v0.7 and the parent's decisions log is updated when v0.7 lands (see §9).

## 1. Goal

Add the siege gameplay: Builders that construct from blueprints and repair, player walls that block movement and sight, Diggers that carve permanent tunnels and mine gems, and hidden bombs. Everything stays server-authoritative and fog-respecting: no client learns of terrain, walls or bombs its team can't see.

## 2. Decisions (from brainstorming)

| Topic | Decision |
|---|---|
| Starting point | v0.6 ships first (Tasks 12–15 included). v0.7's Phase 0 verifies it. |
| Terrain changes on clients | **Last-seen terrain.** A client learns a tile changed only when its fog sees that tile, like building ghosts. Tunnels dug under fog stay secret. |
| Wall storage | **Terrain tiles** (`TileType.WallBlueprint` / `PlayerWall`) with per-tile owner and health arrays in `SimData`, not building entities. |
| Wall lines | Drag lays a **4-connected** line, so diagonals become a staircase with no corner gaps. Each tile is its own blueprint and charge. |
| Line of sight | Moves to **tile resolution**. Fog cells are 2×2 (`FogCellSize`), so the per-cell "half the tiles are walls" rule would let 1×1 walls be seen through. |
| Building rendering | The known issue "buildings are one GameObject each on clients" is **fixed in v0.7**: instanced client buildings. |
| Construction refund | Full refund on cancel until the first progress tick; none after. |
| Bomb visibility | Sent only to the owner and to players the owner shares vision with, from blueprint on. Never to anyone else, as a record or a ghost. |
| Bomb trigger | Any unit whose owner is on the bomb owner's **attack mask** entering the tile. |
| Digger production | A second item in `SmallUnitSpawner`'s production queue. |
| Builder production | From the HQ (`Base`), which gains a production queue. |
| Numbers | Claude proposes starting values (§3, Phase 8); the owner tunes them in review. All live in `GameConfig.xml`. |
| UI | New command-card entries (Build menu items, Dig, Repair, Cancel, Builder/Digger production) go through Figma and owner approval first. |

### Phase 0: Verify v0.6

Branch `release/v0.7` from the merged v0.6. Run both suites and the perf gate; confirm no known issue targeted at v0.6 is open.

### Phase 1: Terrain-change pipeline

- **Server.** `MapStore` tiles become mutable only through a new `SimCommand.SetTile(tile, type)`, applied by `SimCommandSystem` at the tick boundary. It writes the tile, appends it to `ChangedTiles` (already feeding `SectorFieldCache.Invalidate` in `OrderBook`), and raises `SimContext.TerrainChanged`. Border tiles are rejected.
- **Units on a newly blocked tile** are pushed to the nearest walkable tile at the same boundary.
- **Clients: `TerrainBatch`.** `ReplicationService` keeps, per client, a byte array of the tile values it last sent (initialised from the seed-generated map). Each send, for fog cells the client sees now, tiles that differ are sent as `(index, type)` runs and the array is updated. `ClientWorld` hands them to `MapView`, which patches its texture.
- **Join path unchanged:** clients regenerate from seed and check the hash; changes arrive only as deltas.

### Phase 2: Tile-resolution line of sight

- `SimData` gains a per-tile `OpaqueTile` array (Wall, PlayerWall, Border). `SimVisionSystem.LineOfSight` steps tiles, not fog cells.
- The per-cell `Opaque` table and its summed-area table stay as the open-ground fast path; `SetTile` refreshes the affected cell and the table at the boundary.

### Phase 3: Instanced client buildings

- Replace `UnitCommander`'s per-building GameObjects with a `ClientBuildingStore` fed by `BuildingBatch`, drawn by an instanced renderer (the `ClientWorld` / `InstancedUnitRenderer` pattern).
- Clicks and selection use a tile → building lookup that replaces `BuildingListInsert` and the `SpawnerClientManager` reflection mapping.
- Ghosts, blueprints and bombs use the same store.

### Phase D: Command-card additions in Figma

Design and get owner approval for: Builder build menu (Miner, Spawner, Wall, Bomb), Cancel construction, Repair, Dig, HQ production (Builder), Spawner production (Tank, Digger), and the blueprint/under-construction look. No UI production code before approval.

### Phase 4: Builder and construction

- `UnitType.Builder`, produced from the HQ's new production queue.
- **Blueprint.** `CreateBuilding` creates the building entity with `Construction { Progress }`. The full cost is taken at placement (`TryAddBuilding`). While under construction, health = max × progress (minimum 1); it can be attacked and destroyed; it doesn't produce, mine or give sight beyond 1 tile.
- **Cancel** (new `[Command]`): full refund if `Progress == 0`, otherwise removed without refund.
- **`SimConstructionSystem`** (tick stage, after movement): every Builder with a Build or Repair order whose target is within 1 tile of its position adds `BuildPower × dt` to that target. Progress is summed in a job and applied at the boundary.
- **Orders.** Placing a building with Builders selected gives them a Build order; Shift queues it on the v0.6 waypoint queue. Right-clicking a damaged own or allied building or wall gives Repair.
- **Repair** spends `RepairCostPerHealth` through `Sim.Spend` and stops while the owner can't pay.
- Builders don't attack (`Damage` 0, no target acquisition). They build everything except the HQ.

### Phase 5: Walls

- `TileType.WallBlueprint` (walkable, see-through) and `TileType.PlayerWall` (blocks movement and sight). `SimData` gains per-tile `WallOwner` and `WallHealth`.
- **Placement.** A wall-drag `[Command]` takes start and end tiles; the server rasterises the 4-connected line, validates each tile (ground, in bounds, in range of `CommandValidator` limits, no building), charges per tile, and skips tiles it can't afford or place.
- **Construction** uses Phase 4's build power. It starts only when no unit stands on the tile; the tile then becomes `PlayerWall` with health scaling with progress.
- **Combat.** Walls join the target search through a wall lookup next to the building hash. Units attack walls when ordered to; on attack-move only when no enemy unit or building is in range. Damage uses the existing `Wall` class in `<DamageTable>`.
- **Destruction** sets the tile to `Ground` through `SetTile`.

### Phase 6: Digger

- `UnitType.Digger`, from `SmallUnitSpawner`'s queue.
- **Dig order** (new `[Command]`): a target tile. The Digger walks to the nearest floor tile adjacent to the line toward the target, then digs tile by tile along it.
- **Rock** (`Wall`) takes `DigTime` seconds per tile, then becomes `Ground`. **Player walls** are dug by damage (Digger's `Wall` multiplier). **Gems** pay `GemPayout` to the Digger's owner, then become `Ground`; any Miner adjacent to that tile stops producing.
- **Border tiles** can't be dug (server check and `CommandValidator`).
- Diggers fight if attacked or ordered; the damage table makes them weak against units and strong against buildings and walls.

### Phase 7: Hidden bombs

- `BuildingType.Bomb`, 1×1, walkable. Built by Builders like any building.
- **Interest.** `BuildingInterest` sends a bomb (blueprint or built) only to its owner and to players the owner shares vision with. It is never a ghost for anyone else.
- **Trigger.** A tick stage checks unit tiles against bomb tiles; any unit whose owner is on the bomb owner's attack mask triggers it. The blast deals `BlastDamage` to every unit, building and wall within `BlastRadius`, including the owner's.
- **Effects.** The explosion reaches every client whose fog sees the tile (existing explosion path) and raises the owner's "bomb triggered" alert.

### Phase 8: Numbers and close-out

Starting values (owner tunes in review):

| Value | Proposed |
|---|---|
| Builder cost / upkeep / health / speed / sight | 60 / 2 / 60 / 5 / 6 |
| `BuildPower` per Builder | 25 health per second (a 300-health Spawner: 12 s with one Builder) |
| `RepairCostPerHealth` | 0.2 |
| Wall segment cost / upkeep / health | 5 / 0.1 / 150 |
| Digger cost / upkeep / health / damage | 120 / 4 / 120 / 4 |
| Digger damage multipliers (Unit / Building / Wall) | 0.5 / 3 / 6 |
| `DigTime` (rock) | 1.5 s per tile |
| `GemPayout` | 150 |
| Bomb cost / upkeep / `BlastRadius` / `BlastDamage` | 75 / 1 / 2.5 tiles / 200 |

Close-out: perf gate re-run, docs (`architecture.md`, `gameplay.md`, `known-issues.md`, `CLAUDE.md` "Adding content"), security and code review, a full manual Linux match.

## 4. Security and leaks

- Every new `[Command]` (Build, Cancel, Repair, Dig, wall drag, production) calls `CommandGate.Allow` first and validates ownership, game state (`Playing`) and ranges (`CommandValidator`).
- Bombs never reach a client outside the owner's share-vision set, in any message.
- Terrain deltas reach a client only for fog cells it sees now.
- Wall owner and health reach clients only for tiles they see.

## 5. Testing

- **EditMode rules tests:** refund before and after the first tick; build power stacks per Builder; under-construction health scales; staircase wall rasterisation; construction waits for an empty tile; destroyed wall becomes ground and invalidates paths; tile LOS blocks behind a single wall; border can't be dug; gem payout and Miner stop; bomb damages friendlies; repair stops when broke.
- **LeakTests:** bombs and bomb blueprints never in an enemy `BuildingBatch`; terrain changed under fog not sent until seen; wall data only for seen tiles.
- **FuzzTests:** every new command and `TerrainBatch` decoding.
- **PlayMode:** a hosted match where a Builder walls off, a Digger breaches, and a bomb triggers.
- **Perf:** `tools/perf-run.sh` (tick, pathing and replication all change).

## 6. Exit criteria

Rules tests for every feature; leak tests proving bombs and hidden terrain never reach enemy clients; both suites pass; perf budget met; no known issue targeted at v0.7 open; a full match played on Linux.

## 7. Out of scope

Bomb detection or counters, Builder auto-assist AI, wall gates, the tutorial.

## 8. Effects on later versions

v0.8 now ships first (2026-10-10). v0.7 uses the v0.8 atlases and tile shader; its instanced buildings (Phase 3) read `ArtAtlas` frames instead of per-building sprites, and the Builder, Digger, wall, bomb and blueprint art already exist in the v0.8 manifest.

## 9. Parent-spec decisions superseded on landing

- Walls are terrain tiles, not buildings.
- The client-buildings known issue moves from "fix with walls" to fixed in v0.7 via instancing.
