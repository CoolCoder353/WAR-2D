# v0.12 fixes UX design (Figma)

Designs for the open UX items in [known-issues.md](../known-issues.md) and [bug-review.md](../bug-review.md): the alert feed's position, a squad hint, feedback when an order's goal is moved or the waypoint queue is full, and digging by dragging an area. Same look as v0.8 to v0.12 (Jersey 10, square corners, the `Theme` and `Scale` variables). **No UI production code for these is written until this file records the owner's approval.** A change to an approved frame goes back through Figma first.

- **File:** [WAR-2D v0.6 UX](https://www.figma.com/design/JrMColnJiQbFfODqyPjBYf), page **v0.12 Fixes** (node 77:2)
- **Status:** **Approved** by the owner on 2026-10-18, as drawn, with decisions 1 to 9.

The Play screen's Host text needed no new frame: the approved v0.9 frame `Menu / Play – Friends' games` (37:274) already has "Friends see your game in their list, or you can invite them from the lobby." `HostJoin.uxml` now uses it (2026-10-18).

## Decisions for the owner

1. **Alert position:** right side, directly above the Commands panel, following its top edge as the card changes height (the Builders' card is taller). The alternative is a fixed spot above the tallest card.
2. **Alert emphasis:** bigger rows plus a 3 s border on the newest alert. No sound change (alerts already play their sounds) and no screen-edge flash.
3. **Squad hint:** a one-line hint until the first squad is saved, then tooltips only. The alternative is a permanent `?` on the bar.
4. **Goal moved:** the client works the moved goal out itself (the same `OrderBook.SnapGoal` on its copy of the map), so no new message is needed. It may differ from the server's when the client's map is out of date (fog); the server's goal still wins.
5. **Queued goals while Shift is held:** the client tracks the goals it sent, since the server doesn't send order queues. With a mixed selection the numbers follow the first selected unit.
6. **Queue full:** a Shift-click past the limit is not sent, and the cursor tag says why. Today the server drops it silently.
7. **Dig area:** a new server order (`DigArea`) holding the box. Each Digger picks the nearest unclaimed diggable tile it can reach, re-picking when one is done, until none is left. Shift+drag queues it and keeps Dig armed. Units added to the selection later don't join an area already given.
8. **Dig area size:** at most 24×24 tiles (576); larger boxes are clamped and the tag says "(max)". The cap is a new `GameConfig.xml` number.
9. **Dig marks** are client-side only (your own client draws them from the order it sent), so they reveal nothing to others.

## Built (2026-10-18)

- **Alert feed:** `Theme.uss` `.alert-feed` (right side), `.alert--<kind>` and `.alert--new`; `AlertFeedController` keeps the feed just above `command-card` (it follows the card's height) and highlights an alert for `AlertFeedModel.HighlightSeconds` (`HudTests.AlertFeedSitsAboveTheCommandCardAndHighlightsTheNewest`).
- **Squad hint:** `SquadBar.uxml` `squad-hint`; `SquadBarController` hides it once a squad is saved and sets each slot's tooltip (`SquadBarController.Tooltip`).
- **Order feedback:** `OrderFeedback` (on `UnitCommander`) draws the moved goal, the Shift-held numbered goals and the Dig drag with `OverlayMesh` (tile marks under the fog, lines and rings above it); `OrderTagsController` places the `order-world-tag`, `order-cursor-tag` and `order-number-<n>` labels in `Hud.uxml`. Goals are tracked by `OrderQueueTracker` from `Selection.Ordered`. Rally flags sit at the moved spot.
- **Dig area:** `UnitCommander` runs the drag when Dig is armed and sends `CmdDigAreaChunk` (clamped by `CommandValidator.TryDigArea`, `Orders/MaxDigArea` 24 in `GameConfig.xml`); the server's `DigAreaBook` shares the tiles out (`SimCommandSystem.ApplyDigArea`, `StartAreaDig`). An area Digger walks to a floor tile beside its tile first, and the dig stage measures its line from there, so it never cuts into a tile outside the area. The command card's Dig tooltip and hint use the new copy.
