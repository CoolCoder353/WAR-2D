# v0.9 UX design (Figma)

The Steam screens: a friends' games list on the Play screen, its failure states, and an Invite friends button in the lobby. Same v0.8 look (Jersey 10, square corners, token names unchanged). A change to an approved frame goes back through Figma first.

- **File:** [WAR-2D v0.6 UX](https://www.figma.com/design/JrMColnJiQbFfODqyPjBYf), page **v0.9 Steam** (node 37:415)
- **Status:** **Approved** (2026-10-12). Built as drawn.

## Frame index

| Frame | Node | What it shows |
|---|---|---|
| `Menu / Play – Friends' games` | 37:274 | Host (unchanged) above a **Friends' games** list: host colour, name, mode and map size, players n/8, **Join**; **Refresh** button. **Direct (IP)** is a collapsed section, shown only with `-direct` or in the editor. |
| `Menu / Play – No games found` | 37:289 | Empty list: "No games found. Ask a friend to host, or accept their invite." |
| `Menu / Play – Steam not running` | 37:304 | Warning notice in place of the list; Direct (IP) is expanded (address field and Join) so the screen is still usable. |
| `Menu / Play – Join failures` | 37:319 | The three failure notices: "Game full or already started", "Different game version (host has x, you have y)", "Couldn't reach the host". |
| `Menu / Lobby (host) – Invite friends` | 37:334 | Lobby footer with an **Invite friends** button (opens Steam's overlay invite dialog); the subtitle explains how friends join. |

## Decisions for the owner

1. Layout and wording of the friends' list and notices.
2. Direct (IP) collapsed by default, hidden without `-direct`.
3. The lobby has no joiner-side Invite button (only the host sees it).

## Approval record

Approved by the owner on 2026-10-12 with no changes to the three decisions above (layout and wording, Direct (IP) collapsed and hidden without `-direct`, host-only Invite button).
